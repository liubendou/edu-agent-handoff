# 02 · 工程骨架与三处一致性校验

## 0 本步目标

用 Google 官方多模块脚手架起一个**能编译、能装、能跑校验**的 8 模块骨架，并把「零件目录 / 签名矩阵 / 端侧常量」的一致性问题在编译期就卡死（红线 R-T3、R-T8 的基础设施）。

本步**不做业务功能**，只要骨架绿 + 校验生效。

## 4 完成判据

### 4.1 机检

```powershell
cd d:\agent\edu-agent-kt
.\gradlew clean
.\gradlew assembleDebug      # BUILD SUCCESSFUL，产出 app-debug.apk
.\gradlew test               # 全模块测试全绿（含 contract-check）
.\gradlew contractCheck      # BUILD SUCCESSFUL
.\gradlew detekt             # 允许有既定基线，但不得新增阻塞级问题
```

必须额外成立的两条：

1. **模块与依赖方向**：`settings.gradle.kts` 恰好含 9 个模块；`:core:*` 的 `build.gradle.kts` 中**不得**出现对 `:feature:*` 或 `:ui:*` 的依赖（任何反向依赖即不合格）。
2. **三处一致性的前两处被编译期卡死**：`tools/contract-check` 新增测试断言「`assets/contract/parts.json` 的 16 个 `type` == `:core:model` 的 `PartTypes` 16 个常量」；且该测试**必须能失败**（临时删一个常量即报红，验证后改回）。

## 6 禁止事项

- 不得引入 `libs.versions.toml` 之外的依赖；不得改已冻结版本号（确需新增 → 登记版本目录 + 在 `00-总纲.md` §二 表格补一行，并在汇报里说明原因）
- 不得保留官方模板里用不到的示例模块/示例代码（空壳里不许留 TODO 示例业务）
- 不得在 `:core:*` 里依赖 `:feature:*`；不得建循环依赖
- 不得开启任何跳过校验的开关（R-T4 的同类禁令）
- **minify 保守策略**：debug 不混淆；release 先 `isMinifyEnabled = false` + 注释说明「R8 keep 规则待 `r8-analyzer` 技能验证后在第 10 步决定」，不得擅自开 minify 导致线上崩溃
- 不得把 `assets/contract` 内容复制成第二份硬编码（唯一来源仍是 JSON，Kotlin 常量由脚本或手写但必须与 JSON 断言一致）

## 7 交给下一步的接口

1. **模块与包名**：`com.eduagent.<module>.<layer>`；模块清单固定为 `:app`、`:feature:main`、`:core:domain`、`:core:network`、`:core:data`、`:core:model`、`:core:design`、`:ui:parts`、`:tools:contract-check`
2. **`CatalogVersion`**：`com.eduagent.core.model.CatalogVersion.CATALOG_VERSION`（当前 `1`）——第 9 步断言上下文第 3 段携带该值
3. **`PartTypes`**：`com.eduagent.core.model.PartTypes` 暴露 16 个 `const val`（与 `parts.json` 同序同字符串）
4. **依赖方向**（后续任何步骤不得违反）：`:app → :feature:main → (:core:domain, :ui:parts, :core:design)`；`:core:domain → (:core:data, :core:network, :core:model)`；`:core:data → :core:model`；`:core:network → :core:model`；`:ui:parts → (:core:design, :core:model)`；`:core:design → :core:model`
5. **命令契约**：后续每步机检统一 `.\gradlew :<module>:test`；整体回归统一 `.\gradlew ci`（脚本）或 `.\gradlew contractCheck + test + assembleDebug`
6. **约定插件名**：`eduagent.android.application` / `.android.library` / `.android.compose` / `.android.hilt` / `.kotlin.jvm`，后续模块统一 `plugins { alias(libs.plugins.eduagent...) }`（**具体 id 以本步 `build-logic` 实际注册的为准，须在 `docs\03_工程骨架报告.md` 中逐字写出**）
7. **SDK 与构建配置**：`compileSdk/targetSdk 36`、`minSdk 29`；`kotlin jvmTarget` 与 `JavaVersion` 按官方模板（须在报告中写明）
