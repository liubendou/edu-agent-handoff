## 一、先把设计概念定下来

产品方案从头到尾其实在说一件事：种子、浇水、生长、第二天回来还欠账。界面就该像**一本摊在桌上的本子**，而不是一排货架。由此定三条设计纪律：

- **一次只出现一件事。** 因为用户始终只面对"下一件事"，所以首页是单列流，没有 TabBar、没有九宫格、没有抽屉。
- **会长的东西才配动画。** 内容和掌握度是会长出来的，所以它们有动画；装饰、背景、边框不配。
- **欠账是要还的。** 所以进度不用百分比，用"还剩几张"这种能数出来的说法。

### 1.1 视觉方向：定了，纸与墨

**就这个，不再给备选。** 暖纸底、墨色字，卡片之间不靠阴影分层，靠细线和留白。理由一句话：纸是最不需要解释的阅读载体，跟"本子"这个隐喻是一条线上的；学习产品要被看几百次，花哨的底会先累。

代价也说清楚：它对排版要求高，间距和字重错了立刻显寒酸，没有渐变和阴影可以遮掩。所以下面两张表不是装饰，是这份方案里最需要严格执行的部分。

**颜色**（亮/暗两套值，靠 `prefers-color-scheme` 切同一套语义 token 的值，不是两套图）

| token | 亮色（纸） | 暗色 | 用在哪 |
|---|---|---|---|
| `ambient` 底 | `#F6F3EC` 暖纸 | `#17140F` 暖黑 | 全屏底 |
| `surface` 卡片面 | `#FDFBF6` | `#221D16` | 卡片 |
| `faint` 描边 | `#E4DED2` | `#332C22` | 分隔线、卡片边 |
| `ink` 主文字 | `#221D18` 墨（不用纯黑） | `#EDE7DC` 暖白（不用纯白） | 正文、标题 |
| `ink-soft` 次文字 | `#6B6259` | `#A69C8D` | 出处、说明 |
| `accent` 主色 | `#2E4A6E` 钢笔墨水的靛 | `#7FA0C8` | **只用在"当前这一件事"**：当前卡描边、进度细线、长按波形。不做大面积填充 |
| `good` 对 | `#3E6B4C` 松绿 | `#7FAE8C` | 对 |
| `warn` 模糊 | `#A5761F` 赭黄 | `#CFA152` | 模糊 |
| `bad` 错 | `#A5402F` 砖红 | `#D07A69` | 错 |

三色是重新校过的：纯红纯绿压在米色底上会发闷发黄，所以分别往砖、松、赭调；主色偏不用红，因为红要留给"错"。

暗色不是另做一套设计，是同一套的低亮度版本：底色用暖黑而不是纯黑（纯黑边上浮不起层级，也费眼），主色和三个反馈色都提亮降饱和——高饱和色压在暗底上会"振动"，这是 Material 暗色规范给的结论，照着做。顺带把"暗室里只有一盏灯"那个想法收在这一档：暗色下只有当前那张卡在亮处，其余退到暗处，正好对上"一次只出现一件事"。

**排版数值**（中文，都带依据）

| 项 | 值 | 依据 |
|---|---|---|
| 正文字号 | 16（不低于 15） | 手机端中文正文主流 15~17 |
| 正文行高 | 1.75 | T/CESS 5—2021：文字高度小于 4.5mm 时，中文行高宜 1.7~2.4 倍 |
| 每行字数 | 20~25 字 | 同上；超了就收窄栏宽，不缩字号 |
| 字号单位 | 相对单位，跟随系统字号 | 无障碍要求，也不写死像素 |
| 正文对比度 | ≥ 4.5:1（WCAG AA） | 上线前实测一遍 |
| 字重 | 正文 400、标题 600，不再往上加 | 纸底上字太粗会糊 |

**字体**：标题上衬线（思源宋体 / Noto Serif SC），正文用系统无衬线，做出"标题像印的、正文像读的"对比。Lynx 支持 `@font-face` 自定义字体，但**要求客户端提供字体资源加载器**——所以按"能加载就用衬线标题，加载不了就退回系统字"来做，别把设计押在字体上。中文栈：`system-ui, PingFang SC, Noto Sans SC`。

**纸纹理**：只做静态、低分辨率平铺，或者干脆不做。绝不上动画表面——纹理跟着位移一起跑，一秒就把"高级"跑没了。

**明确不选 Lynx 官方的 LUNA 设计语言。** 它的渐变是一等材质，实现成本高；更重要的是，"紫蓝渐变 + 玻璃拟态"现在就是 AI 生成界面的默认长相——点开一个 AI 生成的落地页，十有八九长那样。这个产品要的是纸的手感，不是发布会 PPT 的手感。

### 1.2 动效母题：全站只用三个动词

| 动词 | 什么时候用 | 长什么样 |
|---|---|---|
| **生长** | 新东西出现（条目入场、地图点亮、掌握度涨） | 缓出，向上 12px + 淡入，180ms |
| **归位** | 用户拖完松手（揭晓、翻条、地图平移） | 弹簧吸附，**不定时长**，看物理 |
| **落下** | 被判定（对 / 模糊 / 错） | 短促位移 + 颜色，120~240ms |

多出来的动画，先问它属于哪一类；答不上来就删掉。这条规则能挡掉大部分"看起来很忙"的界面。

## 二、一屏一屏长什么样

### 2.1 打开的前半秒

屏幕上先有的是**骨架**，不是白屏。骨架必须定高，否则流会跳。0.5 秒内首条内容出来，音频晚一点到没关系——先给看得懂的，再给听得见的。缓存里有什么就先给什么，首条内容不依赖网络。

### 2.2 首页

> 【2026-10-17 修订】本节对"首页形态"的定义**作废**，以《首屏体验脚本》（已签字，最高事实源）§1/§2 为准：**首屏就是全对话流 + 底部常驻输入框**。原"首启走方案 D 那套小课 / 回访第一屏是今日计划面板、面板下面才是流 / 流是一列竖着的卡片墙 / 底部说困惑入口 V1 只能是'点开写一句话'的文字版"等形态描述随本节一并作废。以下旧文仅作痕迹保留。

先分两种情况（主方案 §6 的条件式首屏）：**首启**走方案 D 那套小课；**回访**的第一屏是今日计划面板——三行、端侧算、零等待：到期 N 张 / 待补讲 X 张 / 今天建议学的一条，一个按钮开始（也可以上滑）。面板下面才是流。

流是一列竖着的。顶部一行欠账（一行字，不是红点，不是卡片墙）。中间是卡片，六种：

| 卡片 | 什么时候出现 |
|---|---|
| 今天该学的一件事 | 每次打开的第一条 |
| 上次没走完的 | 有未完成内容时 |
| 还有几张到期 | 复习队列非空时 |
| 下一步可以学什么 | 有推荐内容时，一次最多两条 |
| 给自己定个目标 | 只在前三天出现，之后不再打扰 |
| 打开即看 | 资源型条目（书 / 课程 / 视频链接）的入口卡，不进复习队列 |

底部常驻两样东西：说困惑的入口和口播条（有音频时才出现）。说困惑这个入口要按主方案 §7.3 的边界收一下——**ASR 只服务档 4 的费曼复述，V1 不做通用语音识别**，所以首页这个入口 V1 是"点开写一句话"的文字版（长按录音留给档 4 的"讲给别人听"）。通用 ASR 上来再把首页入口升成长按说话，否则会出现"能录不能懂"的空壳。

> 【2026-10-17 修订】上句"首页这个入口 V1 是'点开写一句话'的文字版"**作废**：底部输入框是《首屏体验脚本》§1/§2 要求的**常驻**输入框，始终在场，不是"点开才写一句话"的入口。ASR 仍只服务档 4 费曼复述（主方案 §7.3 边界不变）。

自适应按 Lynx 4.0 现成的能力做：折叠屏展开或平板用 `@media (width >= 600px)` 变成"流 + 地图"两栏；暗色用 `prefers-color-scheme` 换一套语义 token（不是换两套图）；布局用 flex + 相对单位，所以折叠、旋转、分屏都不用改代码。

### 2.3 会话页

四档共用一套容器，区别只在步子：

- **快速**：地图先给骨架（3~7 个关键点）→ 30~60 秒口播 → 1~3 个"认得出就行"的自检。
- **复习**：一次一张，先让他答，再揭晓；答完三档反馈。对 / 错可以直接左右滑出去（滑不够回中），"模糊"只能点按钮（见 5.2）。
- **标准**：概念 → 例子 → 反例 → 常见坑，一步一推进；讲完即问，**卡住即降难度补讲**（§10.1③，不直接判错）。
- **高质量**：板块地图 + 进度环，记忆 → 理解 → 应用 → 分析逐级，最后"讲给别人听"。

会话结束不是弹窗庆祝，是一句话收尾加一个"下一个"。

> 【2026-10-17 修订】以《首屏体验脚本》§3 为准：**卡片嵌入对话流**（跟着 agent 一侧，不单独占页）；用户作答后**卡片留在原位变灰、不消失、不跳页**；agent 的反馈（对 / 模糊 / 错）以**对话消息**形式出现在卡片下方。滑动手势保留（现有 UID 的左右滑作答），但它不再是"与对话并列的另一个世界"，只是作答的另一种手感。

### 2.4 其余四个页面

- **地图页**：板块往下钻到单个学习单元，节点上带掌握度，能拖能点。
- **资料库**：切成单元后的列表，分两类摆——知识型条目是可测卡，资源型条目（书 / 课程 / 视频链接）只生成"入口卡（打开即看）"、不进复习队列。V1 不做批量文件导入（内容来源就三条：学习科学元课程、一个真实学科、搜索与识图）。每条都能点回原句——这是主方案 §4.3 的 100% 可追溯硬门槛，达不到的条目会被隔离。
- **我的画像**：全部记录可见，逐条能改能删；两个隐私开关放这里。
- **成长轨迹**：掌握点数、板块掌握度，还有"这根柱子长了"（主方案 §10.2 的第一个信号：FSRS 的 S 稳定度上涨要即时可视化）。**不做连续打卡天数**——主方案 §10.2 把它列进了永不做红线，同样的红线还有可失去的资产、排行榜、按时长给奖，这个页面一个都不做。

### 2.5 首屏（方案 D）与回访第一屏的时间线

第一张表只对**首启**有效。回访用户没有这张表——他的第一屏是今日计划面板，端侧 FSRS 直接渲染，不等网络，所以"零等待"这件事在这一屏比任何动画都重要。

| 时间 | 屏幕上发生什么 |
|---|---|
| 0s | 骨架 + 首条卡容器先出（不依赖网络） |
| ≤0.5s | 首条内容文字出现 |
| 3s | 20~30 秒小课开始，边讲边插问，口播条淡入 |
| 30s | 用户完成第一次"学 + 测"；判定要 <1s 才回来（主方案 §10.3：快速、复习两档 <1s，标准 1~3s，深度秒级），所以按下反馈先给，判定结果异步补上 |
| 180s | 收尾给正向峰值，不给"还有 N 张没做"（§10.2 的峰值-终点律）；这时才露出目标卡（无目标用户成本最低的引导点） |

## 三、招牌时刻：第二天回来还欠账

这是整个产品最该被记住的交互，也是留存真正靠的东西，所以它的设计要写得比别的都细。

用户第二天打开，看到顶部一行：**"今天有 3 张要还"**。不是红点，不是"N 条未读"，像本子上夹的一张便签。他点进去，一次只还一张。

还账这一张卡的作答，就是第五章的"左右滑作答"——右滑=对、左滑=错，滑不够回中；三档按钮仍在，作为兜底（"模糊"只能点）。松手后留 1 秒撤销窗口，因为这一下直接写 FSRS 参数，按错就是记错。

每还一张，屏幕右下角那一条细线缩短一格。这条线就是主方案 §10.1 要的"进度条填充"，只是不做成横贯全屏的粗条，也不给百分比，让他一眼看见"还剩两格"。会话本身是有界的——开场就说清"再 3 张清完今天"，不做开放结尾，因为越接近终点动机越强（目标梯度效应）。

三张还完，不弹窗，不过度庆祝。屏幕上先给正向峰值——"今天你变强在哪"（§10.2 的峰值-终点律：收尾不给"还有 N 张没做"），再加一句"今天没有欠账了"，加上掌握点数轻轻跳一下（也就是 S 上涨那根柱子长了一点）。这一下跳跃要好：它是他今天唯一的奖励，所以弹簧要软一点、幅度小一点，不能像游戏抽卡。

卡住的那张，当场降一档难度再插一小段补讲（产品方案 §10.1③：卡住**先降难度、给脚手架，不是直接判错**），补完这张重新排回队列。这一步很关键——**他不该有"错了一题就欠得更多"的感觉**，所以补讲必须立刻发生，不能留到"下次再说"。补讲后再答对，就是 §10.2 说的"挣扎后想起来"，这是最高价值的一次正反馈，反馈要打得比一路顺答更足。

这三步的动画只用"归位"这一条曲线，不加别的动词。仪式感来自节奏（一次只还一张、走一格），不来自特效。

## 四、界面只需要这些零件

产品方案的组件目录给了八个原语，够用。我补了八个，都是"流"和"会话"跑起来必需的：

| 零件 | 什么时候上场 | 一句话 |
|---|---|---|
| `ConceptCard` | 快速 / 标准 | 一个定义加出处，能展开 |
| `QuestionCard` | 复习 / 标准 / 高质量 | 正题或变式，等他答 |
| `RevealCard` | 复习 / 快速 | 上滑揭晓，答案在背面 |
| `MapView` | 快速 / 高质量 / 地图页 | 概念之间的关系图，能拖能点 |
| `ProgressRing` | 高质量 / 成长 | 掌握度；S 上涨时它长一格，是 §10.2 第一个信号的落点 |
| `ExplainStep` | 标准 / 高质量 | 步骤序列，一步步走 |
| `ChoiceGrid` | 复习 / 标准 | 选项，可单选可多选 |
| `MicButton` | 档 4 费曼复述 | 长按说话；首页那个入口 V1 是文字版，不是这个零件 |
| `TTSBar` | 快速 / 标准 / 高质量 | 播、停、倍速、重播（§7.3：TTS 覆盖四档） |
| `FeedbackBar` | 复习 / 标准 | 对 / 模糊 / 错，三档；按下反馈先行，判定异步补上 |
| `SourceLink` | 全站 | 点回**出处原句**（句子级 span）；§4.3 的 100% 可追溯硬门槛落在这 |
| `DueChip` | 首页 | "还有几张"，点开就还 |
| `TodayPlanPanel` | 回访第一屏 | 三行端侧算：到期 N 张 / 待补讲 X 张 / 今天建议学的一条（§6 条件式首屏） |
| `EntryCard` | 首页 / 资料库 | 资源型条目（书 / 课程 / 视频链接）的入口卡，打开即看，不进复习队列 |
| `StreamSkeleton` | 首屏 | 骨架，必须定高 |
| `SessionEndCard` | 会话尾 | 收尾，"下一个"；给正向峰值不给欠账 |

三条规则：

1. **catalog 是产品级全局常量，全量常驻；技能包只按名引用、不内嵌。** 每个零件在 catalog 里声明字段，Skill 只能填声明的字段。想加字段就是改 catalog，不是偷偷塞进 props。
2. 收到目录里没有的组件名，降级成纯文本块渲染，**绝不白屏**。首屏直出加降级兜底，永远不留空屏。
3. 视觉一律用 className + token 注入，行为状态内建。学 lynx-ui 的做法：无样式 primitive，别做成"加个需求就得加个 prop"的黑盒。

### 四·补 对话外壳组件（客户端本地，不进 catalog）

> 【2026-10-17 修订 / 依据《首屏体验脚本》§1 与《改造清单_首屏对话化.md》§2】

首屏对话化新增四个**对话外壳**零件：

| 零件 | 什么时候上场 | 一句话 |
|---|---|---|
| `MessageBubble` | 全对话流 | 单条消息气泡（左 agent / 右 user） |
| `Composer` | 全对话流底部 | **常驻**输入框 + 发送键（V1 无麦克风，体验脚本 §7-2） |
| `TypingSkeleton` | 进入瞬间 | 打字态骨架；**必须可被真实内容替换**（体验脚本 §4-4） |
| `MessageList` | 全对话流 | 对话流容器：渲染对话项，卡片项挂到 `A2UISurface` 现有渲染器上 |

**这四个一律是客户端本地组件：不注册进 catalog，也不出现于 surface registry。**

理由是 **catalog 属于字节级稳定前缀**（主方案 §7.2 / §7.7②：产品级全局常量，跨所有用户、所有档不变）——一旦把外壳组件塞进 catalog，其**序列化结果就变**，命中前缀即被打断，**触发 DeepSeek 上下文硬盘缓存失效**，代价远大于收益。故外壳由客户端本地 `src/chat/` 渲染；卡片仍走原路：A2UI 组件节点 → `A2UISurface` 渲染，只是被包进对话项里。

## 五、手指按下去之后发生什么

### 5.1 手感的三条原则

1. **即时反馈不能等后台线程。** 手指落下这一下必须本帧就有反应，不能走"事件传到后台、处理完再传回来"。
2. **跟手就是 1:1。** 拖拽期间手指移动多少，界面就移动多少，不做平滑、不做插值。
3. **松手交给物理。** 停在哪由弹簧决定，不由定时长决定。

### 5.2 一串有名字的动作

**选一个答案。** 手指落下，选项立刻缩到 0.97 并亮起描边；松手回弹，其余选项退到次要。整个过程不需要后台线程参与，答完再把结果报上去。为什么这么做：答题是最高频的动作，它的反馈延迟会被无限放大。

**揭晓。** 手指往上拖，卡片跟着手指走，答案从下面露出来；松手弹簧吸附到底。这是复习档最核心的一下，必须逐帧跟手，不能用"松手再播动画"。

**左右滑作答（只复习档）。** 卡片跟手横移，右滑过阈值判"对"、左滑判"错"，背面透出对应颜色；松手弹簧吸附。三条约束：只有复习档开；滑动**只映射"对 / 错"两档，"模糊"永远走按钮**（滑不出来）；松手后留 1 秒可撤销——这一下会直接写进 FSRS 参数，滑错就是记错，得给反悔的机会，撤销条压在卡片下方，不做弹窗。阈值取卡片宽度的 30%，滑不够就回中、不算数。

于是同一张卡上有三个手势意向：上拖揭晓、竖滑翻条、横滑作答。按第六章的原则，**从手指落下就一起判**，主轴等位移超过 8px 再锁定（见附录），不是先判一个方向、失败了再试下一个。

**翻到下一条。** 竖滑，当前条跟手移出，下一条跟手进入，松手吸附。用 lynx-ui 现成的 `Swiper`（它就是把进度映射成位移/透明度的那套做法），不自己写。

**长按倾诉。** 只在档 4 的"讲给别人听"里出现（主方案 §7.3：ASR 只服务档 4 的费曼复述，首页那个入口 V1 是文字版，见 2.2）。按住 350ms 判定成功，波形开始画；提前松手就是取消。阈值和 lynx-ui `Draggable` 的长按档对齐，全站只有一个长按标准。

**口播条。** 播放、暂停、倍速图标即时切换；进度条跟手拖动。回答"他听到哪了"这个问题，只靠眼睛。

**点开欠账。** 按下有反馈，然后进复习会话（见第三章）。这一下不要花哨，它是每天都要走的路。

**拍照。** 从相机回来先进"正在看"的状态，分析在后台跑；不让他盯着空白等。

**地图上走。** 单指拖，图跟手；点节点，节点轻轻放大一下、相关的连线亮起来。用来回答"这块和那块什么关系"。

**跳过 / 收工。** 条目移出，"连续两次跳过"就是他要收工的信号，交给自适应那边。

### 5.3 主线程脚本的写法

想在主线程同步响应，事件名加 `main-thread:` 前缀，处理函数第一行写 `'main thread'`：

```tsx
// 即时反馈：本帧生效，不走后台线程
const onTapOption = (e: MainThread.ITouchEvent) => {
  'main thread';
  e.currentTarget.setStyleProperty('transform', 'scale(0.96)');
  runOnBackground(reportAnswer)(id);   // 结果上报，不占手感
};
```

```tsx
// 跟手：滚动位置在主线程直接拿到
let onScroll = (e) => {
  'main thread';
  e.currentTarget.setStyleProperty(
    'transform',
    `translateY(${500 - e.detail.scrollTop}px)`,
  );
};
```

反面例子，别这么写：

```tsx
// 逐帧 setState：后台线程往返一趟，手感必然滞后
const onScroll = (e) => { setOffset(e.detail.scrollTop); };
```

跟在后面要记住的五件事：

1. 主线程函数捕获的外部变量只在组件重渲染时同步一次，而且必须能 `JSON.stringify()`；**不能在主线程里改外部变量**，要跨调用记状态就用 `useMainThreadRef()`。
2. 主线程函数之间可以互相调；跟后台线程只走 `runOnMainThread` / `runOnBackground`，**只在结果上报时用**，不做逐帧往返。
3. 要复用代码就 `import ... with { runtime: 'shared' }`，第三方库（比如 motion）也这么引。
4. 需要"条目真正上屏"的时机，用 `main-thread:ref`。普通 `useEffect` 和 `ref` 在条目没上屏时也会触发，别拿它们驱动逐帧逻辑。
5. `useLayoutEffect` 不支持；布局完了要立刻改样式，用 `main-thread:bindlayoutchange`。

### 5.4 判定回来之前不空等，三档反馈一眼分得清

**判定有快有慢（主方案 §10.3：快速、复习 <1s，标准 1~3s，深度秒级）。** 所以按下那一刻的反馈必须本帧就给，判定结果异步到了再补"对 / 模糊 / 错"。中间这段时间不留空：他按下去了，界面就得有反应，不能盯着一个静止的选项等模型。

复习档只给三个答案，这三个答案就是它全部的反馈语言：

- **对**：绿描边加勾，卡片轻轻上移 4px，120ms。
- **模糊**：黄调加灰化，卡片下沉 4px，180ms。**"模糊"不是废票，是脚手架的入口**——选它就走"再讲一遍"（§10.1③），不记账。
- **错**：红描边，卡片下沉 4px，120ms。

这一条我改了上一版：**"错"原来是横向抖三下，现在改成下沉、不抖。** 理由是主方案 §10.1③ 要"卡住先降难度、给脚手架，而不是直接判错"，§10.2 又要求奖励"挣扎后想起来"——抖是惩罚性表达，跟一个学习产品要的正反馈拧着。真正判错之后走的是"当场补讲 → 重新排回队列"（第三章），不是一个扣分动作。

**同一张卡，"直接答对"和"挣扎后答对"的反馈不一样。** 后者是 §10.2 的"模糊 → 对"，也是最值得被看见的一次正反馈，所以绿描边之外多给一下——勾画得更实，成长轨迹上那根柱子多长一格。

振动这版先不做，但这条值得重开：Apple HIG 说得很清楚，动效不能是唯一的信息通道，得用触觉和声音补上；社区已有 `@sigx/lynx-haptics` 这类包，映射到 Android 的 `Vibrator` / `VibrationEffect`，成本不高——就看要不要在"吸附到位"和"判定对错"这两个时刻给一下反馈（见第九章）。另外，系统开了"减少动态效果"就关掉所有位移，只留 120ms 的透明度切换。

## 六、苹果和大厂定过的几条规则

这一章不是我的偏好，是有出处的。看完就明白第五章的手感，以及附录里那些参数为什么长这样。

**触摸后 1~2 帧内必须有应答。** 苹果在 WWDC18《Designing Fluid Interfaces》里用 10ms、50ms、100ms、200ms 的延迟梯度演示过：过了 100ms，界面就像"掉下了悬崖"，不再是手的延伸。所以按下态的应答要落在 1~2 帧内（16~33ms），并且不能等后台线程。

**动画要允许被打断、被反转，并从当前位置和速度接着跑。** 同一场演讲里，苹果判断用户中途是不是要停，看的是**手指加速度的突变**，而不是等一个计时器——"越快地停下，我们越快能检测到"。这条直接决定选型：可能被打断的动画不要用定死的 CSS 关键帧，要用主线程里可读可写的数值来驱动（`@lynx-js/motion/mini` 的 MotionValue，每次 `animate()` 从当前值继续往下走）。Material 3 的官方说法是同一件事——弹簧用于"可能被中断或由手势驱动"的动画，曲线只用于"不会被打断、也没有手势"的动画。

**松手时把手指的速度交给弹簧，而不是从零开始播一段动画。** 苹果把这条叫"轻的交互、放大的输出"：手指只移动几毫米，界面得靠位置、速度、加速度去推断意图，再把结果放大。所以方向判定要看速度，不能只看松手时的位移——"轻轻扔一下"也该算数。

**多个手势从一开始就同时监测。** 苹果的原则是"当出现多个手势时，从一开始就同步监测它们"，不要先锁定一个方向再等另一个；响应重定向要尽可能快。落到实现上：竖滑和横滑从手指落下就一起判，而不是先判竖、失败了再判横。

**空间一致，边界要软。** 同一个视图从哪进来的，就该从哪出去（从顶部滑下来的东西，不该往侧面消失）。列表滑到头不是硬停，是橡皮筋式减速；原生滚动本来就是这样——保持抛掷动量、摩擦自然减速、最后不知不觉停下。所以滚动交给 `<scroll-view>` / `FeedList`，不要用 JS 重造一套惯性。

**用"行为"思考，而不是"动画"。** 苹果把界面动效分成两种：timed animation（交互之后播一段固定动画）和 dynamic motion（交互持续影响一个动态行为）。放到这份方案里，"生长"和"落下"是定时动画，可以交给 CSS；"归位"是动态行为，必须跑在主线程、由弹簧决定停在哪。

**帧节奏稳，比平均帧率高更重要。** 同样的速度下，30fps 会闪、60fps 不闪——"丝滑"说到底是帧间隔稳不稳。Android 自己的口径也一样：FrameTimeline 判定 jank 的标准是"帧实际呈现的时间与调度器预测的呈现时间不符"，兼容性定义里还要求帧延迟一致（每秒不一致的帧不超过 5 帧，目标低于 1 帧）。所以验收不能只看平均帧时。

**动效要能关，而且不能是唯一的信息通道。** Apple HIG 的 Motion 一章写得很直接：不要为了动而动；动效要可选，不能用它承载唯一的信息，要拿触觉和声音补上。这句是 7.4 的降级档、无障碍开关，以及第九章"要不要做触觉"那个问题的出处。

**再修正我上一版一处：位移和透明度不该共用一条曲线。** Material 3 把弹簧分成两族——spatial（位置、缩放）和 effects（颜色、透明度），而且空间弹簧是**带轻微过冲**的。我上一版那条 `cubic-bezier(.2,.8,.2,1)` 没有过冲，用在位移上偏平、偏钝。M3 给的 Web 换算可以直接搬：空间默认 `cubic-bezier(0.27, 1.06, 0.18, 1.00)` / 500ms，快速 350ms；透明度用 effects 那族 `cubic-bezier(0.31, 0.94, 0.34, 1.00)`，快速 150ms、默认 200ms。如果 Lynx 那边不方便打断，这套曲线就当 CSS 用。

### 6.1 落地边界：一条要实测，两条已经查清

上面那些规则落到 Lynx 上，边界就这三条。第一条接入时实测一次，后两条已经查清了：

1. **Motion 的弹簧能不能吃到手指的初速度。** 官方文档写的是 Motion 的 spring 选项**全部受支持**（stiffness、damping、mass 等），`velocity` 应该在列——所以这条从"未知"降成"接入时实测一次确认"。真吃不到速度，跟手就退化成"从零起步"，手感差一档。
2. **主线程能不能读当前值。** `MainThread.Element.getComputedStyleProperty()` 是存在的，所以"读一下现在到哪，再改目标"这条路通——这是"从当前位置续跑"的兜底手段。
3. **`Element.animate()` 只有 pause / play / cancel，没有 `currentTime`。** 也就是说它没法在时间轴上精确续播；被中断后要接着走，只能读当前样式值再重新起一个动画。CSS 的 `animation-play-state` 同样：能暂停能恢复，但**改不了目标值、不能从当前位置改道**。结论就一句：**可被打断的动画，别用 CSS 关键帧。**

## 七、动画凭什么不卡

### 7.1 三档动画，各归各的手段

| 这一档动画 | 走什么 | 为什么 |
|---|---|---|
| 手一碰就发生的（按下、选中、图标切换） | CSS `transition` / `@keyframes` | 引擎自己插值，不花 JS |
| 被看见的（条目进出、页面转场、进度环、地图点亮） | CSS，需要物理感时用 `@lynx-js/motion` | 一次性启动，之后不占主线程逻辑 |
| 跟手跑的（揭晓、翻条、地图平移、拖进度条） | **主线程脚本**，或 lynx-ui `Swiper` / `Draggable` 的主线程回调 | 逐帧，必须和手指同频 |

**一条硬分界（来自第六章）：能被打断的动画不要用 CSS 关键帧。** 按下、选中这类"你松手它也结束了"的反馈交给 CSS 没问题；但凡是可能被中途反向、或者要接力跑的（拖拽、吸附、翻条），一律用主线程的弹簧数值驱动。分界线是"这一下会不会被打断"，不是"它长不长"。

能用现成的就别自己写：流式长列表和下拉刷新用 lynx-ui `FeedList`，翻条用 `Swiper`，拖拽用 `Draggable`（它自带 `onMTSDragging` 等主线程回调）。动画库用 `@lynx-js/motion`（直接复用 Motion 源码，跑在主线程），首版建议用 `mini` 入口，约 135KB，只支持数字——够用，等真的需要颜色和单位字符串再升全量。

### 7.2 十条禁令

1. 动画只改 `transform`、`opacity`、`z-index`。改宽高、left/top、内外边距、边框宽度，等于在动画帧里做测量和重排，直接打回。
2. 动画进行中不增删节点。流式追加要等本条动画走完，或者干脆无动画入场。
3. 同一时刻并发动画不超过两个，多的排队；同屏 stagger 最多六条。
4. 列表滚动期间不触发测量，不在主线程做 I/O。
5. 图片定尺寸、先给占位、提前预加载；解码和纹理上传不落在动画关键帧上。
6. 音频解码不落在动画帧上，首段先备好再播。
7. 跨线程消息节流批量，不做高频往返。
8. 后台超过 50ms 的活儿切分。
9. `<blur-view>` 不进逐帧路径——Android 上它是 Lynx 自研实现，需要抓取背景元素，只在出现那一刻做一次淡入。
10. 低端机、省电模式、"减少动态效果"三种情况走 7.4 的降级档。

属性能不能动画，以官方 `@keyframes` 和 CSS properties 文档为准，不要照着 Web 的经验猜。

### 7.3 怎么证明它不卡

用官方的 Trace 加 Recorder。时间线上看 `Choreographer#doFrame`（UI 线程）加 RenderThread `DrawFrames` 的和值：

- 和值 ≥ 32ms：红；16~32ms：橙；< 16ms：绿。

红橙帧优先查。官方给的归因就四类：主线程被测量/布局或 I/O 堵住、布局与绘制过重、图片解码和纹理上传卡在关键帧、JS 长任务和高频跨线程消息。

验收门槛先定这几条：

- 首页滚动、翻条、地图平移三种场景：红橙帧占比低于 3%，P95 帧时低于 16.7ms。
- 首屏 0.5 秒内有内容，任何情况下不白屏。
- 冷启动到能动手，中端机不超过 1.5 秒。
- 至少跑一台中端机和一台低端机，不能只在开发机上验收。
- **帧间隔要稳，而不是平均帧时好看。** 苹果和 Android 的口径都指向帧节奏：同速下 30fps 会闪、60fps 不闪；Android FrameTimeline 把"实际呈现时间与调度器预测时间不符"判为 jank，兼容性定义要求每秒不一致的帧不超过 5 帧、目标低于 1 帧。所以除了 P95 帧时，还要单独看**同一次交互里的帧间隔方差**，一次抖动比整体慢更伤手感。

内存用 Lynx 4.0 的全局查询（按 Elements、UI Views、主线程 runtime 分类）定期快照，排查因为内存压力引起的抖动。

### 7.4 降级三档

| 档 | 什么时候用 | 表现 |
|---|---|---|
| 完整 | 默认 | 全部动画加弹簧、stagger、毛玻璃 |
| 精简 | 低端机、省电模式、检测到持续抖动 | 关掉 stagger 和抖动，时长打六折，**跟手保留**（这是核心手感，不能砍），毛玻璃关闭 |
| 静止 | 系统"减少动态效果" | 只留 120ms 的透明度切换；跟手位移仍是 1:1，但取消弹性吸附 |

判定和切换都在后台线程做，切换本身不能引起界面跳动。

## 八、我替你定了的事

这些不用再讨论，理由各一句：

- **不用 LUNA**：渐变一等材质成本高，且那是 AI 生成界面的默认长相。
- **不做 TabBar / 九宫格 / 抽屉**：出现菜单就等于要求用户做决策，跟"种子应用"直接冲突。
- **毛玻璃只用两处**：顶部状态区和底部常驻栏，不进动画路径。
- **长按统一 350ms**：和 lynx-ui `Draggable` 的长按档对齐，全站只有一个标准。
- **退出动画永远比进入快**：退出是"离开"，不该让人等。
- **stagger 只对首 6 条生效**：长列表逐条入场会把首屏拖慢。
- **虚拟列表不自研**：用 lynx-ui `FeedList`，它已经把虚拟列表加下拉刷新加加载更多做完了。
- **不做共享元素转场**：用 transform 近似（放大 + 位移），省掉一整套跨层实现。
- **跟手动画只在复习和快速两档启用**：标准、高质量的讲解页不做跟随类动画，减少复杂度。
- **可被打断的动画不用 CSS 关键帧**：CSS 关键帧能暂停恢复，但改不了目标、不能从当前位置改道；要接力跑就得用主线程的数值驱动。
- **位移和透明度用两套曲线**：空间动画带一点过冲（实物感），透明度不过冲（否则显脏）。
- **手势从手指落下就同时判两个方向**：苹果的原则是多手势同步监测，先锁一个方向再等另一个，会漏掉用户中途改主意的动作。
- **滚动惯性不自研**：保持抛掷动量、摩擦减速、最后无声停下，这是原生滚动已经做好的事。
- **判定优先级：卡住先降难度、给脚手架，不直接判错**（§10.1③）。判定反馈按 §10.3 的时延走——按下反馈先行、判定异步补上，中间不留空。
- **收尾只给正向峰值，不给欠账**：说"今天你变强在哪"，不说"还有 N 张没做"（§10.2 的峰值-终点律）。
- **四条红线一个不做**：连续打卡天数、可失去的资产、排行榜、按时长/卡数给奖（§10.2）。成长轨迹页因此只有掌握度，没有连胜。
- **会话有界，不做开放结尾**：开场就说"再 3 张清完今天"，配那一条进度细线（§10.1①）。
- **左右滑作答只复习档开，且只映射"对 / 错"**："模糊"永远走按钮；松手留 1 秒撤销（误滑会写错 FSRS 参数，代价太高）；同一张卡上三个手势从落下就一起判，主轴 8px 后锁定。

## 九、还有一件事要你拍板

**加不加触觉反馈？**
我上一版把振动直接砍了，调研之后觉得砍早了。Apple HIG 明确要求"动效不能是唯一的信息通道"，要拿触觉补；用手抓一下、卡片吸附到位、判定对错，这三个时刻给一下触觉，是 iOS 和大厂高级感里很实在的一部分，而且和"减少动态效果"开关天然互补（关了动画的人反而更依赖触觉）。社区有 `@sigx/lynx-haptics` 这类现成包，映射到 Android 的 `Vibrator` / `VibrationEffect`，不用自己写。代价是多一个依赖、多一层真机适配。

> v1.3 已经把"算力位置、资料形态、账号与推送"锁死了（云侧 LLM、三层内容来源、无账号本地优先且不主动推送），这份文档就按这个来：**不做登录墙、不做云同步、不做推送**。真正会改动设计的只有上面这一件。
