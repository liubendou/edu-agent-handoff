## 1. 学习模式体系（五档）

### 1.1 五档定义

| 档位 | 目的 | 心理学取向（示例） | 可感知行为 | 主要命中零件 | 入口 |
|---|---|---|---|---|---|
| 快速学习 | 建立骨架 / 考前速览 | 提取练习、组块化、首因-近因 | 回合短、卡片流、几乎不追问 | 要点卡、讲解卡、对比卡 | 首屏 chip |
| 标准 | 常规学习 | 精细加工、自我解释、双重编码 | 讲解 + 提问 + 小结各一轮 | 讲解卡、题卡、判题卡 | 首屏 chip |
| 深度 | 吃透一个板块 | 费曼、苏格拉底追问、认知负荷调控 | 多轮追问、要求复述、出图 | 讲解卡、地图卡、题卡、错因卡 | 首屏 chip |
| 复习 | 抵抗遗忘 | 间隔重复、交错练习、检索优先 | 由队列驱动，用户不选内容 | 复习卡、进度卡 | **独立入口**（今日复习） |
| 提分 | 结果导向提分 | 目标设定、诊断归因、刻意练习 | 先诊断再定计划，按计划推进 | 诊断卡、计划面板、题卡、进度卡 | **独立入口**（提分） |

**五档的差异化手段**（避免"只是模型档位不同"的伪差异）：
1. 技能模板不同（指令骨架、输出结构不同）
2. 心理学子集不同（每档只注入该档相关的条目）
3. 交互节奏不同（追问密度、是否要求复述、是否强制出题）
4. 命中零件与校验签名不同
5. 模型档位**不参与**差异化（用户手动选，默认 Flash）

### 1.2 复习档与复习队列

- 端侧维护复习队列：`知识项 × 复习档期 × 掌握度 × 上次表现`
- 触发：打开 App 时端侧算出"今天该学什么"（本地计算，不走网络）
- 队列优先级：逾期项 > 薄弱项 > 新学项（具体权重 [待确认]）
- 间隔重复算法：SM-2 还是 FSRS [待确认]；建议 FSRS（对个体记忆建模更好，但需要更多历史数据，冷启动阶段可先用 SM-2）
- 数据：本地优先（SQLite），跨设备同步 [待确认]

### 1.3 提分技能（你的定义 + 落地路径）

**第一步：区分长期 / 短期**（你的要求）
- 首次进入提分入口时**明确询问一次**：「你是想在某个考试前突击，还是这学期稳步提升？」
- 询问结果写进用户画像，之后**自动判定**，不再重复问
- 也可以从输入里推断（出现"下周考试""月考"→短期；出现"期末""这学期"→长期），推断出结果时给一句确认卡片即可

**短期路径（考前突击）**
1. 诊断薄弱项（成绩单识图 / 错题 / 快速摸底题）
2. 锁定高频考点与命题规律（搜索工具介入）
3. 高频考点逐个突击（快速学习档复用）
4. 计时训练 + 应试策略（时间分配、取舍题）

**长期路径（稳步提升）**
1. 诊断现状与目标（目标分数 / 院校 / 排名）
2. 目标拆解到周计划（计划面板）
3. 每周计划执行 + 错题归因（错因卡）
4. 阶段自测 → 回写掌握度 → 调整计划

**数据依赖**：成绩单（识图 OCR）、错题记录、目标（分数/院校）、可用学习时长
**待确认**：短期窗口如何定义（7 天 / 30 天？）、是否接入"考试日历"、提分是否需要家长视角的周报

## 2. 心理学方法论库（79 条）

### 2.1 建议分类（6 族）

| 族 | 覆盖内容 | 主要服务的档位 |
|---|---|---|
| 记忆与巩固 | 间隔重复、提取练习、精细复述、组块化 | 复习、快速 |
| 理解与建构 | 精细加工、自我解释、双重编码、类比迁移 | 标准、深度 |
| 练习与迁移 | 交错练习、刻意练习、变式训练、即时反馈 | 提分、标准 |
| 元认知与自我调节 | 计划-监控-反思、校准自信、错因归因 | 深度、提分 |
| 动机与情绪 | 目标设定、胜任感、焦虑调节、成长型思维 | 全档位（尤其提分） |
| 习惯与节奏 | 启动摩擦、番茄节奏、微习惯、恢复策略 | 复习、长期提分 |

### 2.2 每条条目的字段结构（建议）

```
id / 名称 / 一句话原理 / 适用档位 / 触发条件 /
注入形式（指令·卡片结构·节奏控制）/ 证据出处 / 反例（什么时候不该用）
```

「反例」字段很重要：79 条之间会互相冲突（例如"降低认知负荷"与"制造必要难度"），冲突时必须有优先级裁决，否则模型随机取用会导致体验不一致。

### 2.3 注入策略 —— 两个方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 全量常驻 | 79 条全文放在缓存断点前 | 实现最简单，缓存命中便宜 | 固定前缀可能达 16k–30k token，每回合都在为用不到的条目付费 |
| B. 索引常驻 + 按需注入（**推荐**） | 断点前只放 79 行索引；每回合按「档位 + 技能 + 用户状态」检索 3–8 条全文注入到断点后 | 前缀小、命中率高、成本可控 | 需要一套检索规则（可用轻量规则表，不必上向量库） |

[待确认]：选 A 还是 B。选择会直接改变上下文装配与成本模型。

## 3. 用户自适应（画像系统）

### 3.1 记什么

| 类别 | 例子 | 敏感度 |
|---|---|---|
| 学业身份 | 学段、年级、学科、目标 | 低 |
| 学业表现 | 成绩单、错题、薄弱知识点、自测结果 | **高** |
| 学习条件 | 每日可用时长、学习时段偏好 | 低 |
| 偏好 | 讲解风格、例子偏好、语言风格、节奏 | 低 |
| 情绪与禁忌 | 介意的事、焦虑触发点、鼓励方式偏好 | **高** |

### 3.2 何时记（触发机制）

- 硬触发器：会话即将结束、用户上传资料（成绩单/课本）、用户明确表达偏好、阶段自测完成
- 提取：由模型从对话中抽取结构化条目（不是全文存档）
- **落库前给用户一次可见确认**：「我记住了这 3 件事」+ 可改可删 —— 这一步是建立信任的关键，也是隐私合规的抓手
- 用户可随时查看/删除全部画像（画像可见页）[待确认：是否进 v1]

### 3.3 怎么用

- 注入八段上下文的「用户画像」段
- 分层：**稳定画像**（学段、目标、偏好、禁忌，长期不变）+ **近期状态**（最近薄弱点、最近情绪、当前进度），后者每回合可变
- 长度控制：画像段设硬上限，超限时按"影响当前回合决策的程度"裁剪

### 3.4 存哪

- 本地优先（端侧 SQLite）；敏感条目（成绩、介意的事）默认**不上云**
- 云同步 [待确认：是否进 v1]

## 4. 系统架构

### 4.1 八段上下文装配

| # | 段 | 内容 | 变化频率 |
|---|---|---|---|
| 1 | 系统约束 | 角色、安全、格式、校验规则 | 版本级 |
| 2 | 心理学库 | 方案 A 全文 / 方案 B 索引 | 版本级 |
| 3 | A2UI 目录 | 16 个零件的 schema + 版本号 | 版本级 |
| — | **↑ 缓存断点：以上三段必须逐字节稳定 ↑** | | |
| 4 | 技能模板 | 当前档位的指令骨架 | 选档位/技能时变 |
| 5 | 用户画像 | 稳定画像 + 近期状态 | 会话间变 |
| 6 | 任务指令 | 本回合具体任务（含端侧算出的"今天学什么"） | 每回合变 |
| 7 | 历史 | 对话历史（需截断策略） | 每回合追加 |
| 8 | 按需检索 | 命中才注入的资料片段 / 搜索结果 / 心理学条目全文 | 命中才注入 |

**缓存注意**：
- DeepSeek 的上下文缓存是 **per-model** 的 —— Flash 与 Pro 各有一份，切换模型即断缓存
- 所以"失败自动升级"如果频繁来回，缓存在两边来回重建，成本反而上升。建议：**升级到 Pro 后锁定 Pro 直到会话结束** [待确认]
- A2UI 目录带版本号是正确做法：端侧升级零件时版本号变化，缓存自然失效，不会出现新旧 schema 错配

### 4.2 Validator（技能签名校验）

- 规则：每档技能声明一组**必需零件签名**（见 §5.2），模型输出必须命中签名集合，否则判废
- 位置：**端侧渲染前**（省一次云请求，且错配的 UI 不会被渲染出来）
- 兜底链路（**推荐，[待确认]**）：
  1. 判废 → 自动升 Pro 重试一次（带失败原因回灌）
  2. 仍判废 → 降级为纯文本回答（不用零件，保证有内容）
  3. 三级都失败 → 明确告诉用户"这次没组织好，我换个说法"，并埋点告警
- 绝不允许静默失败或空白回合

### 4.3 端侧（Lynx 4.0）

- 渲染 A2UI 指令 → 16 个原生零件；主题/组件体系复用现有实现
- 端侧职责：校验签名、算"今天该学什么"、维护本地队列与画像、离线兜底（无网时至少能复习已有队列）
- 目录版本：端侧目录版本号写入上下文第 3 段，保证云侧生成的指令与端侧零件匹配

### 4.4 一次学习回合的完整链路

1. 用户输入（文字 / 拍照 / 上传资料）
2. 端侧：识别意图 + 读本地状态（画像、队列）→ 算出"今天该学什么"与建议档位
3. 端侧 → 云侧：带上档位、任务指令、画像摘要、检索需求
4. 云侧：装配八段上下文 → 调 Flash（默认）
5. 模型：按技能模板生成 A2UI 指令（只选零件、不写代码）
6. 端侧：validator 校验签名 → 通过则渲染；不通过走 §4.2 兜底
7. 交互：用户做题/追问/复述 → 结果回写
8. 回写：更新掌握度与复习队列、更新画像（触发 §3.2）、写埋点

## 6. 首屏与首次体验（v0.1 提案）

骨架 = **DeepSeek 式极简 + 豆包式能力推荐位**（你指定的方向），落成具体形态：

1. **中央问候语**（唯一会变的内容）：结合时段 + 上次进度 + 目标，例如"晚上好，昨天那道三角函数你差最后一步，今天接着来？" —— 自适应能力的第一个可感知证据
2. **下方大输入框**，占位文案直接教用法："问一句就行，或者拍张课本 / 成绩单"
3. **输入框上方模式 chip**：首屏只露 `快速 | 标准 | 深度`；**复习**与**提分**走独立入口（首页的"今天要学"卡 + 横滑卡），避免五个 chip 破坏零门槛
4. **输入框下方横滑卡**（借鉴豆包推荐位，只放 4 张）：`拍课本` `传成绩单` `今日复习` `提分计划`
5. **不做底部 Tab**：历史会话左上角、画像与资料库右上角；理由见风险 §9
6. **首次进入不做教程**：第一次学习时用一张"我怎么带你学"的卡解释三档差异，一次性、之后不再打扰
7. 空态用 3 张可点示例卡（点一下真的开始学），不写说明书

## 7. 内置工具

| 工具 | 用途 | 呈现方式 |
|---|---|---|
| 联网搜索 | 考点/命题规律/教材版本差异/时效性内容 | 工具卡（必须含来源） |

## 8. 埋点与指标（建议）

- 激活：首日完成一次"完整学习回合"的比例（不是首次打开比例）
- 留存：7 日回访率、复习队列完成率
- 体验：validator 判废率、升级率、平均回合时长、首屏到首次提问的耗时
- 效果：自测正确率变化、错题重做正确率、计划完成率
- 成本：单回合 token 消耗、缓存命中率

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 判废整回合导致空白/反复重试 | §4.2 三级兜底，绝不静默失败 |
| 79 条心理学互相冲突 | 每档标定冲突裁决优先级，「反例」字段强制填写 |
| 小学到大学跨度太大，一套系统约束不适用 | 系统约束按学段分变体 [待确认] |
| 成本失控 | Flash 默认 + 前缀缓存 + 索引式心理学注入 + 画像段硬上限 |
| 首屏信息过载（五档 + 工具 + 横滑卡） | 首屏只露 3 档 + 1 排横滑，其余进独立入口 |
| 敏感数据（成绩、介意的事）泄露风险 | 本地优先、敏感项不上云、画像可见可删 |
| 学习效果无法证明 | 用错题重做正确率与阶段自测作为硬指标 |
