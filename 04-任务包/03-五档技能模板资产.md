### 3.1 目录与文件（5 个目录必须齐全，命名逐字如下）

### 3.2 `skill.json` 字段（key 名逐字一致，12 项不得缺失）

```json
{ "mode": "quick", "id": "skill.quick", "name": "快速学习", "version": "1.0.0",
  "instruction_skeleton": "<Markdown 正文，与同目录 prompt.md 同源>",
  "output_contract": { "required_parts": ["keypoint_card","explain_card"],
                       "optional_parts": ["compare_card","table_card"],
                       "emit_order": ["keypoint_card","explain_card"] },
  "required_parts": ["keypoint_card","explain_card"],
  "optional_parts": ["compare_card","table_card"],
  "rhythm": { "prompt_density": "low", "require_recap": false, "force_quiz": false },
  "psychology_tags": ["记忆与巩固","理解与建构"], "tau": 0.18,
  "source_refs": ["assets/contract/signature-matrix.json#quick", "存量素材:skill包/quick-learning/SKILL.md"] }
```

| 字段 | 类型 | 约束 |
|---|---|---|
| `mode` | enum | ∈ `quick`/`standard`/`deep`/`review`/`boost`，且等于目录名 |
| `id` | string | 固定 `skill.<mode>` |
| `name` | string | 中文档名，与 §5 表中文名一致：快速学习 / 标准 / 深度 / 复习 / 提分 |
| `version` | string | 本资产自版本，统一 `1.0.0`；**禁止**写入契约 §1 的库版本号 |
| `instruction_skeleton` / `output_contract` | string / object | 骨架正文与 `prompt.md` 同源，**不得**含时间戳、日期、UUID、会话 ID（§6 R-T2）；`output_contract` 键为 `required_parts`/`optional_parts`/`emit_order` |
| `required_parts` / `optional_parts` | string[] | 见 3.3，**必须逐字等于** `signature-matrix.json` 同档值 |
| `rhythm` | object | 三键齐：`prompt_density`(enum `low`/`mid`/`high`)、`require_recap`(bool)、`force_quiz`(bool) |
| `psychology_tags` | string[] | ∈ 第 4 步 6 族名（见 7 接口），至少 1 项 |
| `tau` | number | 见 3.4，与 `motion-tokens.json` 同档值一致 |
| `source_refs` | string[] | 契约锚点 + 存量素材路径；证明可追溯（呼应 R-C1） |

### 3.3 `required_parts` / `optional_parts`（**逐字抄 §5 签名矩阵**；零件 `type` 必须 ∈ `parts.json`）

| mode | required_parts（缺任一 → 判废） | optional_parts |
|---|---|---|
| `quick` | `["keypoint_card", "explain_card"]` | `["compare_card", "table_card"]` |
| `standard` | `["explain_card", "quiz_card", "verdict_card"]` | `["keypoint_card", "review_card"]` |
| `deep` | `["explain_card", "quiz_card", "map_card"]` | `["error_cause_card", "compare_card"]` |
| `review` | `["review_card", "verdict_card"]` | `["progress_card"]` |
| `boost` | `["diagnose_card\|plan_panel", "quiz_card"]` | `["progress_card", "error_cause_card", "material_card"]` |

> boost 的「诊断卡 **或** 计划面板」在本步统一编码为单元素字符串 `diagnose_card|plan_panel`（`|` = 二选一）。
> 编码形式以第 1 步 `signature-matrix.json` 的**实际写法为准**：动笔前先读该文件，逐字对齐，不得自创第三种写法。

### 3.4 五档 `tau`（逐字抄 §8.5 / D29，首版固定）

| mode | quick | standard | deep | review | boost |
|---|---|---|---|---|---|
| `tau` | 0.18 | 0.25 | 0.35 | 0.15 | 0.30 |

### 3.5 `rhythm` 建议取值（本步冻结，供第 9 步 TASK 段与埋点使用）

| mode | `prompt_density` | `require_recap` | `force_quiz` | 依据（设计 §1.1） |
|---|---|---|---|---|
| `quick` | `low` | `false` | `false` | 回合短、卡片流、几乎不追问 |
| `standard` | `mid` | `false` | `true` | 讲解 + 提问 + 小结各一轮 |
| `deep` | `high` | `true` | `true` | 多轮追问、要求复述、出图 |
| `review` | `low` | `false` | `false` | 队列驱动，用户不选内容 |
| `boost` | `mid` | `true` | `true` | 先诊断再定计划、按计划推进 |

> `force_quiz = true` 的档（`standard`/`deep`/`boost`），其 `quiz_card` **必在**对应 `required_parts` 内；
> `quick`/`review` 置 `false`，**禁止**为了「凑题」投递矩阵外零件（会被埋点记 `unknown_part`）。

### 3.6 boost 档长短期分叉（D1 / D32，必须写进 `instruction_skeleton` 与 `prompt.md` 正文）

| 分支 | 判定条件（D32） | 骨架必写句 |
|---|---|---|
| 长期 `LONG` | 无考试日 **或** 距考试日 > 30 天 | 「先诊断现状与目标 → 目标拆解到周计划 → 每周执行 + 错因归因 → 阶段自测回写掌握度」 |
| 短期 `SHORT` | 距**用户自填**考试日 ≤ 30 天 | 「先诊断薄弱项 → 锁定高频考点 → 逐点突击 → 计时训练 + 应试策略」 |
| 首次 | 进入提分入口**第一次** | 「**只问一次**」长短期问询 → 结果写入画像 → 之后**自动判定**，不再重复问（验收 C1.6） |
| 落点 | DataStore 键 `boost_horizon` ∈ `SHORT`/`LONG` | 常量 `SHORT_WINDOW_DAYS = 30`；**考试日历 v1 不做**，日期由用户手填 |

### 3.7 附属文件

**`references/*.md`（该档专属资料索引）**：必须存在 `references/资料索引.md`（可再按主题拆多个）；内容为**该档专属资料的清单/索引**（题源、教材映射、模板、检查清单指针），不抄契约与原始文档全文；每份索引须含出处列（呼应 R-C1），且**不得出现 Lynx / TS / 前端框架字样**。
**`prompt.md`（人类可读骨架正文）**：与 `instruction_skeleton` 同源，结构固定为 `何时进入本档 → 输出结构（零件与顺序）→ 节奏（追问密度/复述/出题）→ 心理学取向 → 结束与回写`；必须能让非程序员**一眼区分五档**（见 4.2 检查点 1）。

## 5 本步红线

| ID | 红线 | 本步落地方式 |
|---|---|---|

## 6 禁止事项

1. 禁止写任何 Kotlin / Compose 实现代码或 Gradle 逻辑（机检任务除外，须先申请）。
2. 禁止修改 `assets/contract/*.json` 的 schema 或取值；发现不一致只能**汇报**，不得就地改契约。
3. 禁止发明零件 `type`：所有签名串必须 ∈ `parts.json` 的 16 项。
4. 禁止把 `tau`、时长、曲线、弹簧参数写进零件或 `output_contract`（R-T10）。
5. 禁止残留 Lynx / TypeScript / 前端框架痕迹，包括注释、示例、`source_refs` 说明文字。
6. 禁止用「模型档位」（Flash/Pro）做档位差异化——差异化只由技能模板 + 心理学子集 + 节奏 + 签名零件构成（设计 §1.1）。
7. 禁止预写或生成 `assets/psychology/*`（属第 4 步）。
8. 禁止自创与 §5、§8.5 不同的枚举值或版本号。
