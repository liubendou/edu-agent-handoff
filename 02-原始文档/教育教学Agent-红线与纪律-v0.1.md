# 教育教学 Agent · 红线与纪律 v0.1

> 配套文档：`教育教学Agent-设计方案-v0.1.md`（设计 §N）、`教育教学Agent-验收文档-v0.1.md`（验收 §N）
> 效力：本文件中的**红线**为不可协商项，任何角色不得以「先跑通」「临时」「后面再改」为由绕过。
> 违反红线的处理：立即回滚或停止发布，记录事件，并在下一次评审中复盘。
> 变更方式：红线只能通过书面评审新增或删除，不允许默认放宽。
> 标 `[待你确认]` 的条目为我的建议条款，你删掉或改掉即可，改成什么样就按什么样执行。

---

## 1. 这份文档解决什么问题

三件事：**不许做什么**（红线）、**必须怎么做**（纪律）、**在哪一步被谁拦住**（检查点）。

适用对象：产品、客户端、服务端、内容（技能模板与心理学条目）、测试。

---

## 2. 产品红线（R-P）

| ID | 红线 | 为什么 | 拦截点 |
|---|---|---|---|
| R-P1 | 首屏不得出现教程、引导弹窗、多步设置向导、注册墙 | 产品承诺是「点开即用」；任何前置教学都在否定这个承诺 | 设计评审 + 冷启动走查（验收 X1.1） |
| R-P2 | 首屏不得出现第 4 个及以上的模式 chip | 五个 chip 会把「不用学」直接变成「先做选择题」 | 设计评审 + 验收 X1.2 |
| R-P3 | 不得出现空白回合、静默失败、无解释的转圈 | 用户会认为产品坏了；一次就够流失 | 代码评审 + 验收 S1.8 |
| R-P4 | 不得对用户做价值判断（"你基础很差""这题都不会"） | 教育场景的伤害远大于一般产品 | 系统约束评审 + 内容抽查 |
| R-P5 | 不得使用成瘾式留存机制：连续打卡断签惩罚、攀比排行榜、限时恐吓、虚假进度条 `[待你确认]` | 我们要的是「学会」，不是「停留时长」；这是教育产品的底线 | 设计评审 + 埋点审查 |
| R-P6 | 不得向未成年人路径植入诱导消费、抽奖、付费弹窗 | 合规硬要求 | 设计评审 + 验收 P3.3 |

## 3. 技术红线（R-T）

| ID | 红线 | 为什么 | 拦截点 |
|---|---|---|---|
| R-T1 | 模型**只输出目录内的零件指令**，绝不输出可执行 UI 代码（HTML/JS/CSS） | A2UI 的核心安全边界；一旦放开，端侧就等于执行任意远端代码 | 代码评审 + 抓包比对（验收 K1.2） |
| R-T2 | 断点前的三段（系统约束 / 心理学库 / A2UI 目录）**必须逐字节稳定**。禁止插入时间戳、用户名、随机 ID、随会话变化的任何内容 | 前缀缓存是成本模型的地基，一处动态内容全盘失效 | 代码评审 + 连续 50 次请求哈希比对（验收 S1.2） |
| R-T3 | 任何新增零件必须同时更新：端侧目录、云侧第 3 段、**技能签名矩阵**。三者缺一不得合并 | 签名矩阵是 validator 的判定依据，漏更新会导致误判废或漏判废 | CI 检查（三处资产 diff 校验） |
| R-T4 | validator **不得被开关绕过**；禁止为了「先上线」加 feature flag 跳过校验 | 一旦存在绕过开关，它迟早会在生产环境被打开 | 代码评审（禁止新增跳过分支）+ 验收 K1.3 |
| R-T5 | 判废必须走完三级兜底，禁止静默丢弃 | 判废是正常路径的一部分，不是异常 | 代码评审 + 验收 S1.8 |
| R-T6 | 自动升级 Pro **只能发生一次**，禁止升级循环；禁止在非失败场景下自动改用 Pro | 缓存 per-model，来回切模型会让成本反向上升 | 代码评审 + 验收 S1.5 |
| R-T7 | 默认必须是 Flash；任何人不得把默认值改成 Pro | 成本纪律 | 配置审查 + 验收 S1.4 |
| R-T8 | 端侧目录版本号必须写入上下文第 3 段；端侧升级目录后旧版本号不得继续使用 | 防止新旧 schema 错配渲染 | 代码评审 + 验收 K1.7 |
| R-T9 | 不允许为跑通流程而放宽签名矩阵（例如把"必需"改成"可选"） | 签名矩阵是技能可辨认性的唯一保障 | 代码评审（矩阵文件 diff 必须有人评审） |

## 4. 内容与教学红线（R-C）

| ID | 红线 | 为什么 | 拦截点 |
|---|---|---|---|
| R-C1 | 不得编造来源、引用、研究结论、教材页码 | 教育产品的错误会被学生直接背下来 | 内容评审 + 验收 T1.5 |
| R-C2 | 搜索结果与识图结果必须携带来源或可核对原件 | 用户需要能自行验证 | 验收 T1.1 |
| R-C3 | 每一条心理学方法论**必须有证据出处**；无出处的条目不得入库 | 79 条是我们的核心资产，也是最大风险面 | 资产脚本校验（验收 C2.1） |
| R-C4 | 每条心理学条目**必须填写「反例」**（什么时候不该用） | 79 条之间会互相冲突，没有反例就会随机取用 | 资产脚本校验 |
| R-C5 | 每档必须标定心理学冲突裁决优先级，不允许留给模型自由裁量 | 否则同档体验会前后不一致 | 资产评审 + 验收 C2.4 |
| R-C6 | 不得对超出用户学段的内容"硬教" | 认知负荷失控是负面体验的主要来源 | 验收 T1.2 |
| R-C7 | 不得把提分包装成"包过""必提 X 分"这类承诺 | 无法验证的承诺等于虚假宣传 | 文案审查 |

## 5. 心理与伦理红线（R-E）

| ID | 红线 | 为什么 | 拦截点 |
|---|---|---|---|
| R-E1 | 心理学机制**只能用于「让人学会」，不得用于「让人停留」** | 这是本产品最容易走偏的地方 | 设计评审（每个机制必须写明"服务于哪个学习目标"） |
| R-E2 | 不得制造焦虑、羞耻、负罪感来驱动学习（"你落后了""别人都学完了"） | 伤害不可逆，且与长期学习目标相反 | 文案与系统约束审查 |
| R-E3 | 不得基于成绩/表现做人格或能力归因（"你就是不擅长数学"） | 归因方式直接影响学习动机 | 系统约束评审 + 内容抽查 |
| R-E4 | 画像记录**不得推断心理疾病、家庭状况、经济条件**；只记录学习相关的显性事实 | 越界推断既不准也不合规 | 抽取规则评审 + 验收 C3.6 |
| R-E5 | 任何画像写入必须先给用户可见确认；用户拒绝的条目不得入库 | 信任的前提是知情 | 代码评审 + 验收 C3.2 |
| R-E6 | 不得把敏感条目（成绩、情绪敏感点）用于任何形式的对外展示、分享、排行榜 | 一次泄露就无法挽回 | 数据流审查 |

---

## 6. 数据与隐私红线（R-D）

| ID | 红线 | 为什么 | 拦截点 |
|---|---|---|---|
| R-D1 | 成绩、错题、情绪敏感点**默认不上云**；若确需上行必须单独授权 | 最小必要原则 | 抓包审计（验收 P3.1） |
| R-D2 | 用户删除画像必须**彻底删除**（本地 + 云端），不可只做软删除 | 否则等于欺骗 | 验收 P3.2 |
| R-D3 | 用户数据**不得用于训练模型、不得共享给第三方**，除非有明确且可撤回的授权 | 教育数据高度敏感 | 合规审查 |
| R-D4 | 日志中不得出现成绩、姓名、情绪内容的明文 | 日志是最容易被忽略的泄露面 | 日志规范 + 抽查 |

## 7. 协作与变更纪律（D）

| ID | 纪律 | 具体要求 |
|---|---|---|
| D1 | 四类资产受版本控制，变更必须评审 | ① 五档技能模板 ② 79 条心理学条目 ③ A2UI 目录 ④ 签名矩阵。任何一项变更 = 一次评审，不允许"顺手改" |
| D2 | 断点前内容的任何改动，必须先评估缓存影响 | 提交说明中必须写明"是否影响断点前内容"及结论 |
| D3 | 资产变更必须同步更新验收文档对应条目 | 设计改了、验收不改 = 验收失效 |
| D4 | 判废率 / 升级率 / 兜底触发次数必须持续上报，禁止把相关日志降级为 debug | 这三个数是这套架构的健康度指标，看不见就等于失控 |
| D5 | 阻塞级缺陷不允许挂账，不允许"下版本修复" | 见验收 §8 |
| D6 | 不允许未经评审新增任何引导/弹窗/二次确认 | 首屏零门槛是红线，不能被"运营需求"逐步侵蚀 |
| D7 | 提测前必须提供可复现的失败注入手段 | 否则升级链路、兜底链路无法被验收（验收 E3） |
| D8 | 所有"临时方案"必须带到期条件 | 无到期条件的临时方案一律视为永久方案，因此必须走红线评审 |

| 冷启动走查（新用户） | 产品 + 测试 | R-P1、R-P2、D6 |
| 灰度发布监控 | 全员 | R-P3、D4、D5 |

## 9. 例外申请流程

任何一次红线例外，必须留下以下四项，缺一不可：

1. **哪条红线**（ID）
2. **为什么必须例外**（不例外的实际后果）
3. **例外范围与时限**（限定环境 / 限定版本 / 到期时间，无到期时间不予通过）
4. **谁批准的**（产品 + 对应技术负责人共同签字）

例外期间该红线在验收中按"未通过"记录，不得隐藏。

## 10. 建议你确认的条款

| # | 条款 | 说明 |
|---|---|---|
| 1 | R-P5 成瘾式机制禁令 | 是否连"连续学习天数"这种温和形式也禁？我的建议：允许展示，但**不允许断签惩罚与攀比排名** |
| 2 | R-C7 提分承诺禁令 | 是否允许"目标分数"作为用户自设目标（可以），但不允许产品给出提分承诺（不可以） |
| 3 | R-D1 敏感数据默认不上云 | 是否允许"用户显式同意后同步"，还是干脆全部本地 |
| 4 | R-T7 默认 Flash | 是否给"教师/高价值用户默认 Pro"开口子（我建议不开） |
| 5 | R-P6 未成年人合规口径 | 需要你提供目标市场与年龄段，才能把条款写死 |
