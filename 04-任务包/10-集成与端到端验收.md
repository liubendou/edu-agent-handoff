## 4 完成判据

### 4.1 机检

```powershell
cd d:\agent\edu-agent-kt
.\gradlew ci                 # contractCheck + 全模块 test + assembleDebug 一次跑完
.\gradlew assembleRelease    # 允许 debug key 签名；minify 按第 2 步的保守策略执行
powershell tools\acceptance\run.ps1   # 输出 P0/P1/P2 统计与阻塞级缺陷数
```

必须成立：

1. 全量测试全绿，且第 7 步的 **100 次流式收尾压测**、第 9 步的 **50 次前缀哈希比对**在本步回归中同样通过。

3. `redlines.json` 每一条都必须在 `docs\11_红线自查表.md` 中有对应结论，**不允许留空**。
4. `docs\10_集成验收报告.md` 中所有 **P0 项通过率 = 100%**；P1 未通过 ≤ 3 且不影响主链路；P2 可挂账但必须列入遗留清单。

## 5 本步红线

本步是**总检**，契约 §11 全部红线都在检查范围；以下为最易踩的几条：

| ID | 落地要求 |
|---|---|
| R-P1 / R-P2 | 首屏无任何引导与教程；模式 chip 不得出现第 4 个 |
| R-P3 | 任何情况下不得出现空白回合、静默失败、无解释转圈 |
| R-P4 / R-E2 / R-E3 | 文案不得做价值判断、不得制造焦虑、不得做能力归因（文案统一走 `strings.xml` 便于审） |
| R-P5 / R-P6 | 无断签惩罚、无攀比排行榜、无诱导消费；未成年路径无外链与社交入口 |
| R-T1 | 抓包确认响应里**只有目录内零件指令**，无任何可执行 UI 代码 |
| R-T4 / R-T5 / R-T6 | 校验不可被开关绕过；判废必须走完三级；升级只一次且升级后锁定 |
| R-T10 | 零件内不得携带任何动效/时长/曲线参数（`parts.json` 断言 + 代码审查） |
| R-C1 / R-C2 | 搜索结果与识图结果必须带来源或可核对原件；无来源不渲染 |
| R-E5 / R-D1 / R-D2 / R-D4 | 画像落库前可见确认；敏感项不上云；删除彻底；日志无成绩/姓名/情绪明文 |
| D4 / D5 | 判废率/升级率/兜底触发次数可观测（不得降级为 debug 日志）；阻塞级不允许挂账 |
| D6 | 不得未经评审新增任何引导/弹窗/二次确认 |
| D9 | 本步报告签字后，十步线性结束；任何改动走新的评审 |
