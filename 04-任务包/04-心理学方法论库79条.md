### 3.2 `entries.json`：单条 schema（11 个 key 逐字一致，缺一即判废）

```json
{ "id": "PSY-001", "name": "间隔重复", "family": "记忆与巩固",
  "principle": "<一句话原理>", "modes": ["review", "quick"],
  "trigger": "<触发条件：何时该被检索命中>",
  "injection": { "instruction": "<给模型的指令>", "card_structure": "<命中零件与结构>", "rhythm": "<节奏控制>" },
  "evidence": "<证据出处，非空>", "reverse": "<什么时候不该用，非空>",
  "conflict_priority": 1 }
```

| key | 类型 | 约束（违反即判废） |
|---|---|---|
| `id` | string | 固定 `PSY-001` ~ `PSY-079`（零填充 3 位），**全库唯一** |
| `name` | string | 中文条目名 |
| `family` | enum | ∈ 6 族名（逐字，用 §13 D8 **短名**）：`记忆与巩固`/`理解与建构`/`练习与迁移`/`元认知`/`动机与情绪`/`习惯与节奏` |
| `principle` | string | 一句话原理，非空 |
| `modes` | string[] | ∈ `quick`/`standard`/`deep`/`review`/`boost`；全档通用则 5 值全列（不得写「全档位」等非枚举词） |
| `trigger` | string | 触发条件，非空 |
| `injection` | object | 三子键全齐且非空：`instruction` / `card_structure` / `rhythm` |
| `evidence` | string | **非空**（R-C3）；出处不得编造 |
| `reverse` | string | **非空**（R-C4）；写「什么时候不该用」 |
| `conflict_priority` | number | 整数 `1`~`5`，`1` 最优先；同一冲突组内用于并列打破 |

> 族名一律用契约 §13 D8 的**短名**「元认知」；**不得**写成「元认知与自我调节」等变体（同一族，不得另立第七族）。
> `injection.card_structure` 只能引用 §4 的 16 个零件 `type`（∈ `parts.json`），**不得**写动效/时长/曲线（R-T10）。

### 3.3 `families.json`：6 族 + 条目数 + 服役档位

| 族（`family`，逐字） | 覆盖内容（设计 §2.1） | 服役档位 | `count` |
|---|---|---|---|
| `记忆与巩固` | 间隔重复、提取练习、精细复述、组块化 | `review`、`quick` | ≥5，合计 |
| `理解与建构` | 精细加工、自我解释、双重编码、类比迁移 | `standard`、`deep` | ≥5，合计 |
| `练习与迁移` | 交错练习、刻意练习、变式训练、即时反馈 | `boost`、`standard` | ≥5，合计 |
| `元认知` | 计划-监控-反思、校准自信、错因归因 | `deep`、`boost` | ≥5，合计 |
| `动机与情绪` | 目标设定、胜任感、焦虑调节、成长型思维 | 五档（尤其 `boost`） | ≥5，合计 |
| `习惯与节奏` | 启动摩擦、番茄节奏、微习惯、恢复策略 | `review`、`boost` | ≥5，合计 |

**约束**：6 族名逐字；`count` 之和**严格 = 79**；每族 `count ≥ 5`；`modes`（服役档位）为非空子集 ∈ 5 档枚举。
各族最终条数与归位结果须在汇报中列表，供人工核对（验收 C2.1 / D8）。

### 3.4 `retrieval-rules.json`（方案 B 的检索层）

| key | 内容 | 约束 |
|---|---|---|
| `index_line_format` | 固定 `id \| 名称 \| 适用档 \| 一句话原理` | 与 §3.5 `INDEX.md` 同一格式，逐字一致 |
| `injection_count` | `{"min": 3, "max": 8}` | 硬约束 = D19 / C2.3 |
| `retrieval_input` | `mode`（五档）+ `skill`（技能 id）+ `user_state`（画像/队列状态）+ `reverse_filter` | 四类输入固定，不得增删 |
| `selection_rules` | **3~8 条**选取规则，有序 | 见下表示例 |
| `reverse_filter_rules` | 反例过滤规则 | 命中 `reverse` 条件的条目**必须剔除**，日志可证（C2.5） |
| `conflict_priority_by_mode` | 每档裁决优先级表 | 5 档全覆盖，见下表 |

**`selection_rules`（建议 6 条，可等量替换但总数须在 3~8 之间）**：
① `mode` 硬过滤（条目 `modes` 必须含当前档）→ ② `trigger` 命中当前任务/用户状态 → ③ 按该档裁决优先级**从高到低逐族取** → ④ `reverse` 条件命中则整条剔除 → ⑤ 同族取用不超过 2 条、总数封顶 8、下限 3（不足 3 条时降级取同族次优，仍不足则记 `psy_short` 埋点）→ ⑥ 并列时按 `conflict_priority` 升序打破。
**`reverse_filter_rules`**：`reverse` 为条件式描述时，端侧以规则表判定（如「已熟练」→ 不注入重复强化类）；判定为真的条目不入 `RETRIEVAL`，并在埋点记 `psy_filtered`。

**`conflict_priority_by_mode`（R-C5，冻结基准；左高右低）**：

| mode | 裁决优先级（族级，左高右低） |
|---|---|
| `quick` | `理解与建构` > `记忆与巩固` > `动机与情绪` > `习惯与节奏` > `练习与迁移` > `元认知与自我调节` |
| `standard` | `理解与建构` > `练习与迁移` > `记忆与巩固` > `元认知与自我调节` > `动机与情绪` > `习惯与节奏` |
| `deep` | `练习与迁移` > `元认知与自我调节` > `理解与建构` > `记忆与巩固` > `动机与情绪` > `习惯与节奏` |
| `review` | `记忆与巩固` > `习惯与节奏` > `元认知与自我调节` > `动机与情绪` > `理解与建构` > `练习与迁移` |
| `boost` | `练习与迁移` > `元认知与自我调节` > `动机与情绪` > `记忆与巩固` > `理解与建构` > `习惯与节奏` |

> 经典冲突样例（验收 C2.4）：「降低认知负荷（`理解与建构`）」 vs 「制造必要难度（`练习与迁移`）」——
> `quick` 档取前者、`deep`/`boost` 档取后者；输出不得前后矛盾。
