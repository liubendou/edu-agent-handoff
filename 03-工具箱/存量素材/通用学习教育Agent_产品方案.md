# 通用学习教育 Agent · 产品方案（定稿 v1.3）

> 定位：**通用学习/教育类 Agent，不绑定任何科目与学段**，内容由用户自带。
> 形态：种子型应用（点开即用、零学习成本），首页是"流"不是"菜单"。
> 首发：Android；客户端 **Lynx 4.0**；推理走**云侧 LLM API**（DeepSeek）。
> v1.1 增补：**§7.8 Skill 调用率保证机制**、**§7.9 Agent 与提示词设计方法论**。
> v1.2 增补：**§4.3 切分验收标准（灰度判定闸）**、**§7.3 端侧语音工具（TTS/ASR）**。
> v1.3 增补：**§0.1 V1 内容来源三层**（消解"任意学科"与"只有三份语料"的矛盾）、**catalog 全量常驻**（§7.2/§7.6/§7.7 口径统一）、**§10 心流与正反馈机制**。

## 0. 关键决策与前置判断（已锁定）

| 项 | 决策 |
|---|---|
| 推理算力 | **云侧 LLM API**（DeepSeek），模型与路由对用户不可见 |
| 内置模型 | 默认 `deepseek-v4.1-flash`；卡死时向 `deepseek-v4-pro` **单次**升级 |
| API 配置 | **不开放任何用户自填入口**（无 Key、无 base URL、无模型选择） |
| 首发内容语料 | 用户提供的三份文档（见 §0.1） |
| 复习召回 | **不主动推送**；**回访时**可看见今日待办计划（顶部可折叠条、默认折叠）【2026-10-17 修订：原"**进入 App 第一屏必须看见**今日待办计划"作废——**首启无学习数据时不显示**该条，以《首屏体验脚本》§4-8/§7-1 为准】 |
| 账号 | **无账号、本地优先** |

三个基础判断：

1. **产品的留存引擎是"复习"，入口形态是"对话"，两者不是二选一。** 决定留存的是"第二天有没有一张干净的欠账回来还"；而用户接触这一切的入口是一条对话流。
2. **"任意学科都能跑通"必须落在统一数据模型上**（本方案用 **概念 / 判据 / 过程** 三元组 + **ALU 原子学习单元**），而不是为每个科目写一套 Skill。
3. **不重复造轮子。** 复习调度直接用开源 **FSRS**（Anki 23.10+ 默认）；教学 UI 直接用 Lynx 4.0 的 **A2UI 生成式界面**；模型缓存直接吃 **DeepSeek 上下文硬盘缓存**；语音直接上 **sherpa-onnx**。自研的只有"内容结构化"与"四档编排"。

> 【2026-10-17 修订】原第 1 条表述"产品的复利引擎是'复习'，不是'聊天'"**作废**——该表述把"复习"与"对话"对立，是产品被误定性为卡片流、并被主动排斥"聊天"的源头。**以《首屏体验脚本》（2026-10-17 已签字，最高事实源）为准：复习是留存引擎，对话是入口形态。**

### 0.1 V1 内容来源三层（定死，取代原先"语料只有三份"的模糊说法）

V1 的内容从哪来，必须是一句自洽的话。统一为三层：

| 层 | 内容 | 作用 |
|---|---|---|
| **① 学习科学 = 首启元课程** | 《提分方法论》沉淀的学习科学 | **首启语料就是它**——教学习法＝教怎么用这个 App，"体验即教程"双重命中；**承认它是单一域，不伪装成跨域** |
| **② 心理学研究方法 = 首个真实学科** | 两份《四档…资源清单》 | 验证"四档 + ALU 机制"在真实学科上跑通 |
| **③ 搜索 + 识图 = 任意学科的摄入路径** | 单条摄入 | **这才是 V1 里"任意学科"的真实入口**；产物同样要过 §4.3 验收闸 |

由此两条口径一并定死：

- **"任意学科都能跑通"在 V1 的验证层级**＝**机制层**（ALU / 三元组 / A2UI 不认学科）**+ 摄入层**（搜索 / 识图）——不再是一句未验证的声称。
- **V1 不做批量文件导入**（不给已列为第一高危的"切分"环节再加压）；**批量导入列为 V1.x 灰度项，复用 §4.3 同一验收闸**。

## 1. 一句话定位与目标用户画像

### 一句话定位
**一个"会教、会记、会跟"的通用学习 Agent——打开就能开始学任何东西，而且它记得你学到哪、哪里弱、什么时候该回来问你。**

### 目标用户

| 画像 | 描述 | 典型行为 | 核心诉求 |
|---|---|---|---|
| **A. 目标驱动的自学/备考者（主）** | 考研/考公/考证/期末突击的学生与职场人 | 考前突击、临用前抱佛脚、收藏夹吃灰 | 我缺的不是资料，是"替我排好、盯着我复习"的机制 |
| **B. 无目标的兴趣学习者（主）** | 想学点东西但说不出学什么 | 打开后卡在"选什么" | 别让我选，直接喂我一个入口 |
| **C. 即时求解者（次）** | 作业/工作中遇到不懂的点 | 搜一下、问一下就想懂 | "这是什么、怎么用"，一次讲清 |

**设计约束（由画像反推）**：不能假设用户有目标、有计划、有科目，也不能假设他愿意学习"怎么用这个 App"。

## 2. 核心使用循环（行为链条，不是功能列表）

```
打开 → （无需决策）首页直接给出"今天该学的一件事"
     → （3 秒内）看到一句话 / 一张卡 / 一个问题
     → （30 秒内）做一个小动作：答一题 / 听一段 / 说一句 / 点一下
     → （即时）得到反馈：对 / 错 / "有点模糊" / "再讲一遍"
     → （60~180 秒）一次交互自然结束，给一个微成就 + 露出"下一个"
     → （后台）这次交互被记录 → 更新时间表
     → （第二天）首页的东西变了，且复习队列里有到期欠账
```

关键设计：用户**始终只面对"下一件事"**，从不面对"功能菜单"。

### 为什么第二天还会回来（四个牵引力）
1. **欠账牵引**：明天到期 N 张卡，形成类似"未读消息"的轻微牵引（一次只还 3~6 张，正向、不焦虑）。
2. **连续性牵引**：上次没走完的内容还在原位，回来接着走。
3. **个性化牵引**：首页是"为我准备的"——昨天我提到的事，今天出现在这里。
4. **进展牵引**：已掌握点数的成长轨迹可见。

### 为什么它像"种子应用"
- **首次打开没有空白、没有引导教程、没有登录墙。** 系统自带"种子内容"——即 **① 学习科学元课程**（见 §0.1，是单一域，不伪装跨域）。
- 用户**只浇水、不搭架子**：回答/选择一次，系统立刻把它变成一条学习路径。
- **内容自生长**：种子内容 + 用户带入（搜索/识图）的内容 = 越长越厚的学习地图，用户不需要提前规划。
- **交互形似刷短视频**：单条短（30 秒~3 分钟）、有反馈、无决策、可无限续。

## 3. 四档模式的完整产品形态

`快速学习` 与 `快速回顾` 归为**同一档（Quick Skill，一批两用）**，故共 **4 个模式 Skill**。四档均只依赖"学习单元的元数据"，不依赖学科知识。各档的**目标成功率与心流参数见 §10**。

### 档 1 · Quick Skill（快速学习 / 快速回顾，一批两用）

| 维度 | 内容 |
|---|---|
| 用户**看到** | 一张"知识地图卡"：该知识点/板块的骨架（3~7 个关键概念 + 关系），不是全文；可逐点展开 |
| 用户**听到** | 一段 30~60 秒的口播式总览（"这块其实就三件事……"），支持 TTS |
| 用户**被问** | 1~3 个"复述级"自检（"实验 vs 相关，哪个能说因果？"），只要求认得出 |
| 一项**多久** | 快速学习：3~10 分钟；快速回顾：单次 60~90 秒 |
| **进入场景** | 新知识点第一次接触（快速学习）；临考/临用前 5 分钟（快速回顾） |
| **心理学依据** | 认知负荷理论（先给框架、组块化，降低外在负荷）；"地图先于细节"；自检用**低门槛提取**，避免开局挫败 |
| **适用场景** | 完全陌生的领域建立地图；考前扫高频点 |

**两用如何切换**：同一 Skill，由"深度参数 + 时长预算"切换——`预算=长/目标=建立地图`即快速学习，`预算=90s/目标=唤醒`即快速回顾。快速回顾是快速学习的"浅提取"变体，不单独做成 Skill。

### 档 2 · Review Skill（复习模式）★ 本产品的复利引擎

| 维度 | 内容 |
|---|---|
| 用户**看到** | 一张"到期卡"：正面一个问题/一个判据（不是一段教材） |
| 用户**听到** | 默认静默；反馈只给"对 / 错 / 有点模糊"三档 |
| 用户**被问** | "这个你还能想起来吗"——**先让他答，再揭晓答案**（提取练习） |
| 一项**多久** | 10~30 秒/卡；一轮 3~6 分钟 |
| **进入场景** | 算法指定的到期日（遗忘临界点）；用户也可主动进"复习一下" |
| **心理学依据** | 间隔重复（Cepeda 2006）、提取练习（Karpicke & Roediger 2008，约 80% vs 35%）、Bjork "desirable difficulty"；调度层用 FSRS |
| **适用场景** | 所有已学内容的长期保持 |

### 档 3 · Standard Skill（标准模式）

| 维度 | 内容 |
|---|---|
| 用户**看到** | 结构化讲解：概念 → 例子 → 反例 → 常见坑；一次只推进一个知识点，像"长视频解说 + 互动插问" |
| 用户**听到** | 讲解音频 + 适时停顿提问 |
| 用户**被问** | 讲完即问（自我解释/精细提问）："为什么这一步成立？""它和上面那个的区别？"；答错才补讲 |
| 一项**多久** | 5~15 分钟 |
| **进入场景** | 用户想系统学一个知识点/一个小节 |
| **心理学依据** | 精加工、自我解释、精细提问；例子对比；一次一 chunk 的负荷管理 |
| **适用场景** | 常规学习、补漏 |

### 档 4 · Deep Skill（高质量模式）

| 维度 | 内容 |
|---|---|
| 用户**看到** | 一个"板块地图 + 进度环"，进入"吃透一个板块"的长路径 |
| 用户**听到** | 讲解 + 变式挑战的提示 |
| 用户**被问** | 记忆→理解→应用→分析逐级：变式题、迁移题、"讲给别人听"（费曼） |
| 一项**多久** | 单次 20~40 分钟；整个板块跨多天 |
| **进入场景** | 用户想"彻底吃透"（备考重点板块、专业课难点） |
| **心理学依据** | 刻意练习（Ericsson：拆小技能＋即时反馈＋练在能力边缘）、交错练习、变式训练、费曼/自我解释 |
| **适用场景** | 重点攻坚、追求"能复现/能过审"级别 |

### 心理学依据的取舍理由（为什么不是每档都上最强手段）
- **快速档刻意"不上"高难度提取与间隔**：此阶段目标是"看得懂"而非"记得住"。若在此施加 desirable difficulty，会抬高挫败率、赶走新用户。代价是"看懂了≠记住了"——由标准/高质量档补上，复习档兜底。
- **标准档以"精加工"为主、提取为辅**：讲解阶段认知负荷已高，只做"讲完即问"的轻提取。
- **复习档才是纯提取 + 间隔**：此时内容已"学过"，提取增益最大。
- **高质量档引入交错与迁移**：交错对数学/逻辑类收益最大，但"当下感觉更难"，故只在用户明确要"吃透"时才用。

## 4. 四档之间的衔接与内容流转机制

### 4.1 通用机制：任何学科都能拆成"概念 / 判据 / 过程"三元组

- **概念 Concept**：一个术语/对象/定义（"什么是 p 值"）。
- **判据 Criterion**：何时用、怎么区分（"t 检验 vs ANOVA 何时选哪个"）。
- **过程 Procedure**：一组步骤/一个可执行流程（"假设检验五步"）。

四档本质是在三种原语上做不同的 **深度 × 时长 × 操作** 组合：

| 档 | 作用原语 | 操作 |
|---|---|---|
| 快速 | 概念面 + 判据面 | 认得 |
| 标准 | 概念 + 例子 + 判据 | 自我解释 |
| 高质量 | 过程 + 变式 | 迁移/复现 |
| 复习 | 全部（对 ALU） | 提取 |

### 4.2 内容结构化存档：数据模型

```
学科空间 Subject ──< 板块 Module ──< 原子学习单元 ALU
                                        ├─ 类型：概念 / 判据 / 过程 / 资源
                                        ├─ 正题（正面问什么）
                                        ├─ 反面 / 变式（换问法）
                                        ├─ 依赖：前置 ALU（可成图）
                                        ├─ 难度
                                        ├─ 出处（资料/视频/搜索结果 + 句子级 span）
                                        └─ 用户状态（见下）
```

**ALU 的"用户状态"**（每条独立）：

```
状态 status：未见 → 见过 → 学过一轮 → 暂记 → 已稳固
来源模式 from_mode：quick / standard / deep
最近作答记录：对 / 错 / 模糊 + 用时
记忆参数（FSRS）：D 难度、S 稳定度、R 可回忆率、上次复习时间、下次到期
```

### 4.3 内容管线：切分链路（V1 必做）

因为语料是"带链接的资源清单"而非现成卡片，Agent 必须自己切分。对清单条目做**两层分流**：

- **知识型条目**（如档1自检的"p 值在说什么""实验 vs 相关"、方法论里的判据/过程）→ 生成**可测 ALU** → 进复习队列。**这是复习队列的主要来源。**
- **资源型条目**（书/MOOC/视频链接）→ 生成**"入口卡"（打开即看）** + 出处字段，**不直接进复习队列**。

**切分验收标准（灰度判定闸）**
没有可判定的指标，灰度就无法判定"通过与否"。故定义三类指标，**分硬门槛与抽样两类**：

| 指标 | 定义 | 门槛 | 校验方式 |
|---|---|---|---|
| **可追溯率** | 每张卡都能**回链到原文原句**（创建时即存 `出处文件 + 句子级 span`，点卡可跳回原句） | **100%（硬门槛）** | **程序化逐卡校验**：回链存在且原文可命中；不达标者**隔离、不入复习队列** |
| **可判对错率** | 该卡"正面问、反面能明确判对错"的比例 | ≥ 90% | 抽样：每批**分层抽 100~200 张**，LLM 评审规则 + **≥20% 人工抽检** |
| **颗粒度合格率** | 卡的信息量落在"一次能答完、不宽不碎"区间的比例 | ≥ 85% | 同上（抽样） |

- **阈值标注**：以上为**初始值**，用**前两批真实切分**校准。
- **灰度判定规则**：**连续两批达标 → 扩大灰度**；**任一指标未达标 → 退回"种子内容模式"**（此时 Agent 只做装配与变式，不做自动切分）。
- **回链不自研**：创建 ALU 时即写入"出处文件 + 句子级 span"，**直接复用现成的 citation / span-anchor 实现**。
- **批量评审的成本**：走 §7.6 的闲时调度与成本护栏（属非实时任务）。

### 4.4 三份资料的产品角色

| 资料 | 产品角色 |
|---|---|
| **《提分方法论·汇总》** | 沉淀为**学习科学 Skill 的知识库**，并直接参数化四档与自适应：错因四分类→§5 能力画像与定向补漏；1-2-4-7-15→§4.6 冷启动骨架；五级进阶/连对降级→复习卡升降级规则；检索/间隔/交错/自我解释/精细提问→四档心理学依据；三轮复习法+日周月复盘→计划节奏模板；耶克斯-多德森/睡眠→"状态管理"类内容 |
| **两份《四档…资源清单》** | 第一个真实学科（心理学研究方法）的**验证语料** + **首启种子内容**；外部链接（MOOC/B站/YouTube/FORRT…）不是教学内容本身，而是 ALU 的**"出处"字段** + 搜索工具**起始白名单** |

产品机制保持学科无关：任何学科只要按同样的"四档清单"格式给料，或经**搜索/识图**单条摄入（§0.1 ③），就能跑通。

### 4.5 内容如何在四档之间流转（状态机）

```
           【快速档】 建立地图，产出"见过"级 ALU
              │  状态=见过，不入复习队列（或最低优先级）
              ▼  用户决定深入
           【标准档】 学完一个 chunk → 立刻生成 1~3 张复习卡
              │  状态：见过 → 学过一轮；卡入队，初次 due = T+1 天   ← ★"学过 → 待复习"
      ┌───────┴────────┐
      ▼                ▼
   【复习档】        【高质量档】
   消费到期卡         把 ALU 升级为"重点"，生成变式/迁移题
   答对 → S↑ 间隔↑    入队优先级更高、间隔更保守
   答错/模糊 → 间隔↓
   并回落到标准档补讲
      │
      └──── 循环 ────→ 复习队列
```

**三条硬规则**：
1. **快速档默认不产生复习欠账**。
2. **"学过 → 待复习"的唯一入口是"标准档或高质量档真的讲完并自检过"**。
3. **复习失败自动拉起补讲**（复习档答错 → 回标准档 90 秒补漏 → 补完重新入队）。

**允许跳档**：用户可任意直接进入任何一档；系统只做推荐，不强制顺序。

### 4.6 复习队列与间隔节奏的可实现算法

**① 单卡调度：直接采用开源 FSRS**（不自研）
- 每卡维护 `难度 D`、`稳定度 S`、`可回忆率 R`；S = "回忆概率降到 90% 所需天数"。
- 遗忘用幂律曲线（FSRS 采用 `R(t) ∝ (1 + k·t/S)^-0.5`）。
- 调度规则：**按目标保持率（默认 0.9）反解下次到期日**；答对→S↑ 间隔↑；答错/模糊→间隔↓。
- 冷启动：先用 FSRS 默认参数 + 艾宾浩斯骨架 **1-2-4-7-15 天**；积累足够复习记录后切换到个人参数。
- 收益：同等保持率下比 SM-2 少约 20~30% 复习量。

**② 产品化封装（这三层才是自研重点）**
1. **前置归因**：一张卡答错时，沿**依赖图向上游追溯**检查前置 ALU——很多"错"是前置没懂。这是通用机制。
2. **节奏编织（交错）**：一轮复习 = **跨板块抽 5~8 张**，而非同板块连刷；按"当日预算"截断。
3. **首页欠账排序**：按 `R` 值升序，优先展示"最先跌出 90% 保持率"的卡。

**③ 队列来源汇总**：①标准/高质量档讲完生成的卡 ②用户主动收藏/标记 ③**搜索/识图**摄入后转成 ALU 的内容（同样过 §4.3 验收闸）。

## 5. 自适应 Skill 完整设计

职责：回答两个问题——**什么时候该记录、该怎么记录**，并在会话结束时做一次分析与沉淀。

### 5.1 数据模型（四层）

**A. 学习事实层（原子级）**：ALU 级状态/来源/时间/作答/用时；**成绩事件**（科目、时间、总分、分项、**错因四分类**：不会/会用错/审题/计算）；目标+期限+预估投入。
**B. 能力画像层（派生）**：板块掌握度（该板块 ALU 的 S/D 聚合）、错因分布、学习节奏画像（时长偏好/活跃时段/可接受难度）。
**C. 偏好与边界层**：用户**明确表达过**的"介意/不喜欢"（"别用太多类比""别推送""不喜欢被问'听懂了吗'""别用英文术语"）——**硬约束**，写入所有 Skill 输出约束；以及零散但稳定的细节（专业、年级、语言偏好、是否备考、**语速/音色偏好**）。
**D. 会话摘要层**：每次会话结束生成**结构化摘要**（做了什么、卡在哪、下次建议），不是完整闲聊记录。

### 5.2 触发规则（三类）

| 类型 | 触发条件 | 记录范围 | 时延 |
|---|---|---|---|
| **事件触发（即时）** | 作答、发成绩单、明确说"我讨厌X"、切换模式、跳过、长时间停留、放弃 | 学习事实层 / 偏好层 | 即时、轻量、本地 |
| **周期触发（会话内）** | 会话 ≥10 分钟 或 交互 ≥8 次 | 刷新能力画像层 | 会话中 |
| **会话结束触发（主动分析）** | 空闲 >90s / 退到后台 / 连续 2 次跳过 / 主动说再见 | 见 5.3 | 会话尾 |

### 5.3 总结时机：会话结束时如何分析

触发"接近结束"后，读【本次会话摘要 + 已有画像】，产出三样：
1. **一句心理状态推断**（如"今天偏焦虑、想快点看到结果"）——短期，带 TTL。
2. **偏好/边界的新增或修正**——长期，仅在"用户明确声明 或 出现 ≥2 次"时落库（防噪音）。
3. **对下次交互的一条具体调整建议**（如"他上次说讨厌类比，这次少用"）。

**交互方式**：**静默记录，不弹窗、不打断**；在下次首页体现其效果（让用户"感觉到"而不是"被告知"）。

### 5.4 记录粒度
- 学习事实：逐条原子级。
- 偏好/边界：只记"稳定、可复用"的（≥2 次或明确声明）。
- 心理状态：会话级一条，带 TTL（区别于长期人格）。

### 5.5 隐私与遗忘机制（用户可控）
- **可见可改**："我的画像"页可看全部记录、**逐条编辑/删除**。
- **遗忘（TTL）**：心理状态/学期性信息带过期；长期偏好需复现才保留；用户删除即**硬删除**。
- **敏感信息**：成绩单**端侧解析 → 只存结构化数字与分布，不存原图**；**不用于云端训练**。
- **分级开关**：①"学习数据用于自适应" ②"数据用于云端推理"，**分别可控**。
- **端侧为主**：画像与学习数据**默认存端侧**；云端只做推理、不留存。

### 5.6 它如何驱动"学习路径自适应"（而不只是人设）

| 驱动点 | 由哪个字段决定 |
|---|---|
| 首页"今天该学的一件事" | 复习欠账（R 值）vs 新内容 vs 补讲 |
| 默认进入哪一档 / 难度起点 | 能力画像 + 目标紧迫度 |
| 复习节奏（目标保持率、何时催） | 活跃时段 + 目标期限（临近就调高保持率、压缩新内容） |
| 讲法（类比多少、术语密度、例子来源） | 偏好边界层 |
| 定向补漏专项 | 错因分布（"你 60% 的错是审题 → 开审题专项"） |
| 内容优先级 | 目标 + 期限 |

## 7. Lynx 4.0 下的架构建议

### 7.1 总览：Agent 推理 + Lynx 渲染
Lynx 4.0 原生能力正好匹配本产品：
- **双线程架构**：主线程渲染 UI、**后台线程跑 Agent 逻辑与协议解析**（A2UI 就是"协议消息后台解析、UI 更新主线程呈现"，高频输出 UI 片段也不卡）。
- **A2UI（Agent-to-UI 开放协议）** 生成式界面：Agent 一边推理一边流式产出 UI 片段，客户端渐进渲染——**用户不会面对空白等待，而是看着界面长出来**。
- **ReactLynx 首帧直出**：保证"点开就有东西"。
- **`<webview>`（4.0 开源）**：承接需要 Web 能力的外部资源页（MOOC/论文链接）。

### 7.2 Skill 加载与调度
- 每个模式 Skill 是一个**技能包**：`指令/提示词模板 + 所需工具声明 + 数据结构 + 对本档所用组件的**按名引用列表**`。
  **技能包不含各自内嵌的组件目录（catalog）**——catalog 是**产品级全局常量**（见 §7.6/§7.7），技能包只按名引用，避免按档复制目录导致缓存前缀被打散。
- **调度器（Orchestrator）跑在后台线程**：①向自适应 Skill 要"今日决策"；②激活对应 Skill 并组装上下文；③把产出转成 A2UI 消息流下发。
- **下发方式**：Skill 包可配置、可动态加载（Lynx 支持分包与动态加载），支持热更新而不发版。
- 说明：这与 Lynx 自带的"Agent Skills（面向开发者的可观测性/包体积优化等）"是**两个不同层级**，命名不要混用。

### 7.3 内置工具接入（联网搜索 / 识图 / 端侧语音）
- 都定义为 **Agent 可调用的 tool**，由 Skill 按需声明。
- **搜索**：用于"资料库里没有的 / 时效性内容"。约定：**结果不直接展示原始网页**，而是"读 → 提炼 → 转成统一 ALU → 用学习组件讲"，并**必留出处**。这是 §0.1 ③ 的"任意学科摄入路径"。
- **识图**：拍照（拍题/拍书页/拍板书）→ 多模态理解 → 切成 ALU 入库（同样过 §4.3 验收闸）。
- 安全：工具调用有白名单与限额；搜索结果一律"再加工后呈现"。

**端侧语音（TTS / ASR，离线）**——四档都依赖"听"（口播、讲解音频、档4 费曼复述），语音必须进 V1：
- **TTS**：**sherpa-onnx + Kokoro**（中文优先；**Apache-2.0** 可商用），Piper 留作英文备选；**端侧离线合成**。
- **ASR**：sherpa-onnx 流式 zipformer，**只服务档 4 的"讲给别人听"（费曼）**，并**保留文字输入兜底**——**ASR 质量不得阻塞 V1**。
- **体积**：语音模型**按需下载，不打进 APK**（避开安装包体积与首启门槛）。
- **注册方式**：与搜索/识图同一工具注册表，但标注 **`offline: true`**。
- **一致性**：与"待办本地零等待"及"**语音不出端**"的隐私叙事一致——语音数据端侧处理，不上云。
- **接画像**：把**语速 / 音色偏好**接入自适应画像的偏好层（§5.1 C 层）。

### 7.4 端云边界
| 位置 | 存什么 | 职责 |
|---|---|---|
| **端侧** | 学习事实、ALU 状态、FSRS 参数、偏好边界、"我的画像"页 | **确定性调度**（待办/队列/FSRS 本地算，离线可看可清） |
| **云侧** | —— | **生成式讲解**（需联网） |

- **送云最小化**：每次只发"当前 ALU + 最小上下文"，**不发完整画像**；明确声明数据不用于模型训练。
- **离线降级**：待办可看可清（本地）+ 语音（端侧），讲解需联网。
- 端云同步**做成开关**，默认关闭。

### 7.5 任意学科都能跑通
1. **统一内容原语**（概念/判据/过程）+ **ALU** 数据模型——Skill 只认元数据，不认学科。
2. **A2UI 组件目录是为"通用学习"设计的原语组件**（非科目硬编码）：`ConceptCard · QuestionCard · RevealCard · MapView · ProgressRing · ExplainStep · ChoiceGrid · MicButton`。
3. **内容由资料 + 工具驱动**：三个入口——①首启元课程 ②首个真实学科语料 ③搜索/识图单条摄入（§0.1）；代码里不写死任何科目。
4. **验证层级**：机制层（数据模型/组件不认学科）+ 摄入层（搜索/识图）。批量导入待 §4.3 验收闸连续两批达标后开灰度（V1.x）。

### 7.6 内置模型层与路由（用户零配置）

- **不给用户任何 API 配置入口**（无 Key、无 base URL、无模型选择）。
- **默认 `deepseek-v4.1-flash`**，承担 95%+ 日常生成。
- **深度优化：吃满上下文硬盘缓存**（DeepSeek disk caching 默认开启，按**前缀完全匹配**命中；命中价便宜约 1~2 个数量级）：
  - **提示词分两段**：
    `稳定前缀（全局共享）= 系统约束 + 心理学策略库 + 全量 catalog（产品级常量） + 通用规则`
    ／ `其后逐段变易 = ④ Skill 模板 → ⑤ 画像片段 → ⑥ 任务指令 → ⑦ 对话历史 → ⑧ 按需检索`（顺序见 §7.7）。
  - **前缀里绝不插**时间戳、随机 id；**同一会话 history 只追加**；**批量合并**同类请求共享前缀。
  - 端侧按 `稳定/动态` 分层拼装要送云的上下文。
  - **换档只会让第 ④ 段（Skill 模板）及其后的缓存失效**——①②③ 对所有用户、所有档完全一致，属设计内行为，不是缺陷；App 后端单账户代理时，①②③ 前缀被全部请求共享，命中率最大化。
- **卡死升级（学 Trae 的 Advisor 模式）**：
  - **触发信号**：同义重试连续不收敛／工具连续失败／输出反复偏离目标／用户明显不满或纠错／模型自评低置信。
  - **动作**：向 `deepseek-v4-pro` **发起一次请求**拿到"下一步怎么做"，随即切回 Flash 执行。
  - **硬约束**：**每次卡死只升一次**；升级请求上下文最小化（只带"卡在哪 + 目标"）。
  - **留痕**：升级与结果记入自适应 Skill（"这个点在 Flash 上卡过"）→ 以后同类走更稳路径。
- **成本护栏**：用户 token 日预算 + 升级配额；非实时任务（批量切卡、批量评审）调度到闲时。

### 7.7 上下文设计（稳定前缀吃缓存、动态尾段按需注入）

**① 分层组装（固定顺序，稳定→易变）**

| 顺序 | 段 | 稳定性 |
|---|---|---|
| ① | System 约束（角色/工作准则/安全） | **跨所有请求不变** → 最前 |
| ② | 心理学策略库 | 随产品版本变 |
| ③ | **A2UI 组件目录 catalog（全量常驻）** | **产品级常量，跨所有用户/所有档不变** |
| ④ | Skill 模板（当前档位） | 按档变 → **换档时缓存从这一段起失效** |
| ⑤ | 长期记忆片段（端侧画像） | 按用户变 |
| ⑥ | 任务指令（今天学哪个 ALU、什么节奏） | 每轮变 |
| ⑦ | 对话历史（**只追加**） | 每轮追加 |
| ⑧ | 按需检索结果（资料出处/搜索/识图） | 用到才来 |

要点：**①②③ 是字节级固定前缀**（catalog 全量常驻、不随档裁剪），故**换档仅从第 ④ 段起失效缓存**；**⑤画像绝不放进前缀**（按用户变，放前面会打散所有人的缓存前缀），故放任务指令之前，且**画像更新只在回合边界批量落盘**。四档的差别就是这套组装里"注入什么、注入多少"的差别。

**② 记忆分层**：短期=当前会话消息；工作记忆=一次教学回合的 `thought → action（讲解/提问/调工具）→ observation（作答/工具结果）`；长期=**端侧**的 ALU 库 + 画像。**外置化原则**：长期记忆**永不整体入窗**，只按 `当前板块/当前 ALU` 拉片段（just-in-time）。

**③ 动态注入（不全量塞）**：工具结果**先截断/摘要再入窗**（搜索只入"提炼要点 + 出处"）；检索走 just-in-time，用完即弃；**可寻址引用**代替原文粘贴——用 `ALU-id + 出处（书名/链接/页码 + 句子级 span）`，不放整段原文。

**④ 压缩（窗口快满时的保命清单）**
- **必须保住**：①当前学习目标 ②用户约束（偏好边界层"介意/不喜欢"条目）③未完成步骤（讲到哪、下一问、待办队列引用）④关键引用（ALU-id 与出处）⑤未解决错误（复习答错、工具失败的**原文**）。
- **可丢**：久远对话细节、已完成的回合。
- 策略：重要性打分淘汰 + 滑动窗口；**压缩只动后段，绝不改缓存前缀**。

**⑤ 隔离（三个天然 sub-agent 各占独立窗口）**
- **切分器**：读资料 → 只回传 ALU 列表（结构化 JSON），不回传原文。
- **识图**：拍图 → 只回传 OCR/多模态结论 + 切出的 ALU。
- **搜索**：只回传"提炼要点 + 出处"，原文留在子窗口。
主窗口只拿结论 → 不污染、不被中间过程占满。

**⑥ 三条工程硬规矩**
- **结构化格式**：窗口内用标签分段（`<skill>` `<memory>` `<alu>` `<catalog>`），比裸文本稳。
- **防 context rot**：只注入与当前 ALU 相关的内容，宁少勿滥。
- **错误原文保留**：工具失败/复习判错一律保留原始报错与作答原文，不摘要成"出错了"——否则既无法定位，自适应 Skill 也记不对。

### 7.8 Skill 调用率保证机制

> 调用率本质是**召回率问题**，靠四层叠加保证，不指望模型自觉。

**① 触发层（让 Skill 被"看见"且被"选中"）**
- `name + description` 常驻窗口，**正文按需加载**——全量注入正文会稀释注意力、让 Skill 互相竞争。
- **description 写"何时用"而不是"是什么"**：写清触发场景、用户可能说的原话、排除条件。调用率高低基本由这段文字决定。
- **控制数量 + 分层路由**：Skill 越多命中越乱，先按域粗筛、只暴露相关子集。
- 本产品的天然优势：**四个模式 Skill 本身就是四个域**，首页决策已定档 → 候选集只有 1~2 个，命中率天然高。

**② 指令层（让模型愿意且优先调用）**
- 写成**硬约束**而非建议（"匹配时必须先调用对应 Skill，再产出内容"）。
- 优先级链：**用户点名 > description 强匹配 > 默认流程**；都不匹配就走通用回答，不硬凑。
- 给正反例；调用参数少、默认值齐，别让模型因填参数而放弃调用。

**③ 兜底层（不赌模型自觉，最关键）**
- **确定性激活**：首页决策已确定档位时，调度器**直接激活对应 Skill，不经过模型选择**——这是本产品调用率的地基。
- **后置校验**：本场景该用 Skill 却没调，则强制纠偏（验证器回路）。
- **唯一路径**：学习流程不留旁路。

**④ 度量层（闭环才知道有没有效）**
- 埋点记录调用率，并分别留存**漏触发 / 误触发**样本。
- 评测集同时包含"该触发"与"**不该触发（负例）**"用例。
- A/B 调整 description 措辞——成本最低、杠杆最高。

**一句话**：调用率（召回）与误触发（精确）由**同一份 description**权衡；工程上真正"保证"调用率的是**兜底层 + 度量闭环**，而不是把 prompt 写得更恳切。

### 7.9 Agent 与提示词设计方法论（四个 Skill 统一按此规范写）

提示词是**设计决策的沉淀**，不是文案创作。四个 Skill 一律按此顺序产出：

1. **职责边界**——只为一件"需要判断的事"服务（快速给地图／临用唤醒／长期保持／深挖吃透）；能用固定脚本解决的不做成 Skill。
2. **对错判据**——什么产出算成功、什么算失败（例：复习卡必须**可判对错、颗粒度适中、带变式**）。
3. **决策岔口**——把该档任务当状态机，每个需要判断的岔口就是一条规则的来源（"答错→补讲还是跳过""时长到点怎么收尾"）。
4. **失败模式**——预跑"它会怎么搞砸"：讲太长、跳过自检、生成的卡不可测、术语过难、答错不补讲。
5. **条件-动作 + 优先级**——"当 X 时做 Y"；冲突仲裁：**安全 > 用户明确指令 > 效率**。
6. **按真实日志迭代**——看**具体误行为**，一次补一条，不整篇重写。

三个要点：
- **质量来自迭代回路，不来自初稿文笔。**
- **Agent 是四件套**：循环 / 工具 / 记忆与上下文 / 提示词，一起设计；提示词只是最上层"策略层"。
- **能硬约束就别用软提示**：本产品落点——"**讲完必须自检**"由代码强制、"**复习卡必须可判对错**"由 schema 校验、"**上下文组装顺序**"由端侧拼装器固定。

## 8. Android 第一版功能范围

### 做什么（V1）
1. **核心循环**：打开 → 今天该学的一件事 → 一个动作 → 反馈 → 结束 → 明天变样。
2. **四档 Skill**：Quick（两用）/ Review / Standard / Deep 全量。
3. **自适应 Skill（简版）**：事件触发记录 + 会话结束分析 + "我的画像"页。
4. **内置工具**：联网搜索、识图（可简化：仅拍题/拍书页）、**端侧语音**（TTS 供四档口播；ASR 仅档4 费曼 + 文字兜底）。
5. **端侧画像与学习数据** + 隐私开关 + 成长轨迹页。
6. **条件式首屏**：首启走方案 D（语料＝学习科学元课程）；回访第一屏 = 今日计划面板。
7. **内容管线**：三份资料的 ALU 切分链路（知识型 → 可测卡；资源型 → 入口卡）。
8. **模型层**：内置 API + 默认 Flash + 缓存优化 + 卡死升级（用户零配置）。
9. **切分验收闸**：§4.3 三指标（可追溯率=硬门槛；可判对错率/颗粒度合格率=抽样），未达标即退回种子内容模式。
10. **心流与正反馈**（见 §10）：实时难度调节 + 能力增量反馈 + 红线项禁用。

### 明确不做什么（V1）
- 不做账号体系、不做多端同步（本地优先）。
- 不做主动推送/通知（依赖首屏"进入即见计划"）。
- 不做**批量文件导入**与题库/内容编辑器（批量导入列为 **V1.x 灰度项**，复用 §4.3 验收闸）。
- 不做"多学科种子卡轮播"（V1.x 可选增强）。
- 不做社区、分享、排行榜、游戏化商城。
- 不做付费/订阅。
- 不做 iOS / HarmonyOS / Web / 桌面（Lynx 支持，但首发只 Android）。
- 不做端侧大模型（推理走云侧 API）。
- 不做"设置 API Key"页（内置 API，无用户配置入口）。
- 不做真人/直播/社交。

## 9. 这个构想最可能失败的一环

### 最可能失败的一环：**把任意资料自动化、可靠地拆成可复习原子单元（ALU）**

**为什么是它：**
- **留存引擎**是"复习"（2026-10-17 修订：原"复利引擎"措辞随 §0 第 1 条一并作废，见上方 §0 修订注），而复习的前提是**颗粒度合适、不歧义、可判对错、带变式的卡**。
- 把用户给的文档/视频自动切成这样的卡，是整条链路里**自动化难度最高**的一环：切粗了没法测；切细了无意义；缺"判据/反例"则复习退化成"背答案"。
- **失败即核心价值归零**：切得不可靠 → 内容失去**有界目标**，产品退化成**无有界目标的开放式闲聊**；复习队列要么空、要么是垃圾卡，用户 3 天内流失。种子应用的留存**恰恰依赖"第二天有干净的欠账回来还"**。
- 首屏/UI/自适应都可迭代，唯独这一环"不稳则全盘皆输"。

> 【2026-10-17 修订】原表述"切得不可靠 → 产品退化成'再普通不过的聊天窗口'"**作废**——"像聊天窗口"**不再被定义为失败**（以《首屏体验脚本》为准，对话正是产品的入口形态）；真正的失败形态是**无有界目标的开放式闲聊**：有对话、却没有可还的欠账、也没有有界会话。

### 次高风险：首页"今天该学的一件事"决策不准
若系统给了用户根本不在乎的东西，"零决策"的信任会被击穿——因为那意味着"你把选择权交出去了，对方没接住"。

### 缓解建议
- **首版先"人机分工"**：以**已验证的高质量 ALU 种子集**为主体，Agent 只做"装配与生成变式"；"从原始资料自动切分"作为灰度能力验证。
- **给灰度装上判定闸**：切分是否达标由 **§4.3「切分验收标准」** 判定——**可追溯率 100%**（硬门槛，程序化逐卡校验，不达标即隔离、不入队）+ **可判对错率 ≥90% / 颗粒度合格率 ≥85%**（抽样评审）；**连续两批达标才扩大灰度，任一未达标即退回种子内容模式**。
- **风险不因内容来源不同而豁免**：**搜索/识图**摄入的 ALU 与三份语料**走同一条验收闸**（§4.3）。
- 回链（`出处文件 + 句子级 span`）**复用现成实现，不自研**。

## 10. 心流与正反馈机制

> 关联：本节的参数直接约束 §3 四档与 §8 V1 范围。核心是让用户**进入心流**，并让正反馈**持续可得且不反噬**。

### 10.1 让用户进入心流（三条件 → 落到四档）

**① 目标清晰 → 每次只给"下一件事"，且当次有可见终点**
- 开头说明白"这一次要干嘛"——不是板块名，是"这一张卡"。
- 会话**有界**：给"再 3 张就清完今天"这种小目标 + 进度条填充（目标梯度效应：越接近终点动机越强）。**不做开放结尾**。

**② 反馈秒级 → 判定必须 <1s，别让用户等**
- 判定层（对 / 错 / 模糊）**即时给**，不等模型把完整讲解生成完再一起出。
- 反馈**节奏**比反馈长度重要：一轮里"卡片 → 判定 → 下一张"要顺滑。

**③ 难度≈能力 → 这是当前最大的缺口（原设计难度是静态的）**
- **实时调节**：答得快又对 → 立刻升难度 / 给变式；卡住 → **先降难度、给脚手架**，而不是直接判错。
- **目标成功率锚点（交互层）**：快速 ≈90% ／ 复习 ≈85% ／ 标准 ≈80% ／ 深度 70~80%（85% 规则：错误率约 15% 时学得最快）。
- **别混淆两套指标**：以上是**交互层目标成功率**；§4.6 里 FSRS 的 **90% 是记忆层保持率**，二者独立。

**④ 复习档单独处理**：提取练习本就要"难"，别指望它做起来舒服。复习档的心流靠**高频节拍**（卡 → 秒级判定 → 下一张）维持，**不是把题变简单**——复习档调的是**节拍速度**。

### 10.2 怎么持续给正反馈

**绑"能力增量"，不绑"行为量"**——只认三个可测信号：
1. **FSRS 的 S（稳定度）上涨**，即时可视化（"这根柱子长了"）。后台本就在算，顺手变前台，**零新增机制**。
2. **比上次错得少**（同一张卡 / 同一板块）。
3. **同一张卡从"模糊"→"对"**。

**奖励"挣扎后想起来"，不只奖励"答对"**——否则用户专挑简单题躲。把"卡住但最终答对"标成高价值正反馈。

**话术奖励过程、不奖励天赋**：说"你这次是换对方法了"，别说"你真聪明"（能力型表扬会让人回避挑战，过程型表扬提升坚持）。

**收尾用正向峰值，不用欠账焦虑**：结束时给"今天你变强在哪"，而不是"还有 N 张没做"（峰值-终点律）。

**永不做红线**（会反噬内在动机）：
- 连续打卡天数
- 可失去的资产（心 / 火焰 / 体力）
- 排行榜
- 按时长、按卡片总数给奖

### 10.3 四档心流参数表

| 档 | 目标清晰度 | 判定反馈时延 | 交互层目标成功率 | 单次时长 | 心流维持手段 |
|---|---|---|---|---|---|
| 快速 | 一条地图骨架 | <1s | ~90% | 3~10min | 低门槛自检，开局零挫败 |
| 复习 | 单卡一问 | <1s | ~85% | 60~90s/轮 | 高频节拍，先易后难热身 |
| 标准 | 一个 chunk | 1~3s | ~80% | 5~15min | 讲完即问，卡住即降难度补讲 |
| 深度 | 板块 + 进度环 | 秒级 | 70~80% | 20~40min | 变式迁移 + 脚手架，别崩 |
