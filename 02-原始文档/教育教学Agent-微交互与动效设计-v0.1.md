## 0. 三条采纳判定（先立规矩，再谈配方）

任何动效进入本产品，必须先通过这三问；通过不了就不做：

| 判定 | 含义 | 例子 |
|---|---|---|
| **反馈闭环** | 用户的操作有可见终态 | 提交后按钮变「动作中」，判分后有对/错终态 |
| **状态可见** | 后台/异步状态能被看见 | 今日复习待办数、正在等待模型 |
| **空间连续** | 元素是「滑过去」而不是「跳过去」 | 模式切换的选中指示滑动 |

**不采纳**：光斑、渐变流动、波纹、粒子、装饰性 glow —— 这些不解释任何状态，只是好看。`[本文件新增建议：并入红线 R-P5 的同类禁令]`

## 1. 基调（待确认）+ 一条硬边界

**基调待确认**：两种走法，动效规范不因此改变。

| 走法 | 视觉特征 | 参考对象 |
|---|---|---|
| A. 暖纸讲义感 | 纸色底 `#FAF8F4`、深墨字、衬线标题、发丝线、2–4px 小圆角、三档阴影 | 讲义 / 纸质教辅的气质 |
| B. 冷白极简 | 纯白底、无衬线、大留白、弱边框、几乎无阴影 | DeepSeek 式克制 |

> 五档模式的差异是「内容与节奏」的差异，**不要**让五档变成五种配色/五种动效风格 —— 那样会让用户以为在五个 App 之间切换。

**硬边界（重要）**：**动效归零件，不归模型。**
模型只决定「出现哪些零件、零件里放什么」，**不能决定怎么动**。动效必须写死在端侧零件实现里。
理由：① 动效若由模型输出，同一个零件每回合动法不同，会破坏一致性；② 模型输出动效参数等于把视觉控制权交给不可预测的远端；③ 签名校验也管不到动效。

`[本文件新增建议：加入红线 R-T10 —— 模型不得输出任何动效/时长/曲线参数]`

## 2. 动效三档纪律（无障碍是硬约束）

| 档 | 行为 | 触发方式 |
|---|---|---|
| full | 全部动效 | 默认 |
| reduced | 保守：去掉位移与循环，只保留 120ms 内的透明度/颜色变化 | 用户在设置中选，或低端机自动降档 |
| minimal | 全静态：所有动画 duration = 0，**退化为静态或瞬时，不是隐藏** | 系统「移除动画 / 动画时长缩放为 0」→ 强制 minimal，**用户不可改** |

规则：
1. **每个动效组件必须写 minimal 分支**，并保证信息不丢失（用静态样式表达同一个状态，例如答错用红色文案，而不是取消摇头就什么都不发生）。
2. **持续循环动画只在有意义的条件下渲染**（如「今日待复习 > 0」），minimal 档不渲染循环层。
3. 过渡选择：**位移/尺寸/弹性 → 物理弹簧参数**；**透明度/颜色 → 时长 + ease-out**；**流式正文永远匀速，不弹、不回头**。
4. Android 侧需读取系统「移除动画」与「动画时长缩放」，端侧实现映射 `[待确认：Lynx 4.0 读取该系统设置的具体方式]`。

## 3. 时长与曲线 tokens

| Token | 值 | 用途 |
|---|---|---|
| `micro` | 120ms | 按压、chips 选中、hover、颜色切换 |
| `base` | 200ms | 面板进出、toast、卡片入场 |
| `slow` | 600ms | 大范围布局变化 |
| `draw` | 800ms | 描边类（对勾、掌握度环） |

弹簧三档（物理参数，端侧数值积分实现；不要用 CSS keyframes 拼弹性）：

| Token | stiffness / damping | 用途 |
|---|---|---|
| `snappy` | 380 / 30 | 按钮、chips、pill |
| `default` | 260 / 30 | 页面进出、卡片 |
| `soft` | 260 / 26 | toast、面板 |

> 若端侧只能用 CSS transition，则用近似曲线：`snappy → cubic-bezier(0.2, 0.9, 0.2, 1)` / `default → cubic-bezier(0.22, 0.9, 0.28, 1)` / `soft → cubic-bezier(0.25, 0.8, 0.35, 1)`，时长分别 200 / 200 / 260ms `[待确认：Lynx 4.0 是否提供原生 spring 动画驱动]`。

按压反馈统一：`whileTap scale 0.94–0.97` + `snappy`；disabled 时**不播放**按压反馈。

## 4. 微交互配方清单（本产品版）

| # | 配方 | 场景 | 规格 | minimal 降级 |
|---|---|---|---|---|
| 1 | 按压回弹 | 发送、生成、上传、新对话 | scale 0.97 + `snappy` | 无动效 |
| 2 | 模式指示滑动 | 五档切换（快速/标准/深度） | 选中底片从旧位滑到新位（空间连续），200ms | 静态底片，视觉不变 |
| 3 | 选项 chips 弹跳 | 题数 3/5/8、筛选 | 选中 `scale [1, 1.12, 1]` 一次性 + `snappy`；按压 0.94 | 只留填充色变化 |
| 4 | 提交态三点加载 | 生成测验、导入资料、识图 | 三点 `y [0,-4,0]` repeat，相位延迟 `i*0.14`，0.5s/循环；按钮文案换「动作中」并禁用 | 三点改透明度呼吸，不动位移 |
| 5 | 答错摇头 | 判题答错、输入校验失败 | 内容层独立容器 `x [0,-9,9,-6,6,-2,0]`，420ms ease-out | `x` 恒为 0，用红色文案表达 |
| 6 | 答对描边 | 判分行 | 圆圈 `pathLength 0→1`（600ms），对勾延迟 160ms 后描边（800ms），线宽 1.5–1.8 | 直接满描边静态显示 |
| 7 | 等待思考 | 模型首字前 | 占位条 + 光标呼吸；**超 8 秒必须明示「模型正在思考」**；计时用高频直改文本，不走状态重渲染 | 静态「思考中…」文案 |
| 8 | 顶部轻提示 | 导入成功、画像已记录 | 顶部滑入 12–28px + 透明度，`soft`，3.2s 自动退场；**居中必须用外层容器居中，不能靠 transform 位移居中** | 只做淡入淡出 |
| 9 | 待复习呼吸点 | 今日待复习 > 0 | 外圈呼吸扩散 + 静态实心点 | 不渲染呼吸层，保留静态点 |
| 10 | 掌握度增长 | 掌握度环、进度条、提分曲线 | 数值变化时插值增长（400–600ms ease-out），**不来回摆动** | 直接跳到目标值 |

禁忌：不要给「数字变化」加弹跳；不要给长列表每一项都加入场动画（只给首屏可见的 3–5 项）；同一屏同时动画元素 ≤ 4 个。

## 5. A2UI 流式渲染的动效规范（本产品最核心）

模型输出的是「按行组织、为流式设计」的界面指令，所以要**按零件**而不是按字符做平滑。

### 5.1 双层平滑

```
云侧 token 流
   │  ① 粗平滑：按 16ms 帧窗口聚合后再下发（消息数降 10–50 倍）
   ▼       首帧立即下发（保证首字观感）；结束前必须 flush（否则丢尾）
端侧消费层
   │  ② 细平滑：按 tau 匀速消费「行/零件」，而不是每来一个 token 就重建
   ▼       rate = clamp(backlog / tau, MIN, MAX)，积压多则加速追赶，追平则减速
零件渲染：按行到达即入场（讲解卡 → 题卡 → 判题卡 逐张出现）
```

**tau（每档不同的吐字节奏）**：

| 档 | tau | 观感意图 |
|---|---|---|
| 快速学习 | 0.18s | 干脆、节奏快 |
| 标准 | 0.25s | 从容 |
| 深度 | 0.35s | 越高质量越不急，给思考留时间 |
| 复习 | 0.15s | 追求节奏与效率，复习不该有等待感 |
| 提分 | 0.30s | 稳，强调计划感 |

### 5.2 零件入场规范

- 零件到达 → 入场用**透明度 + 上移 8–12px**，`base` 时长；**不要**用缩放弹出（连续弹出的缩放在长回答里会变成噪音）
- 后续零件持续到达时，**已入场零件不得重排**；新零件插在下方，容器只向上补位（避免整屏抖动）
- 零件内部流式文本：匀速吐字，不弹；文本吐完才允许出现交互控件（按钮从 disabled → enabled 用透明度过渡，不做颜色闪烁）
- 零件**更新**（同一零件被替换内容）：只做内容淡入 + 高度平滑过渡，禁止拆掉重建导致闪一下
- 零件**失败/被判废**：走三级兜底（红线 R-T5），视觉上表现为该零件位退化为纯文本段落，不做红色报错框
- 长回答中**不允许滚动抢占**：自动滚动只跟随用户当前视口；用户手动上滑后停止自动跟随

### 5.3 rAF 生命周期铁律（照抄实战结论，防"回答完了还在转"）

1. 循环的结束条件必须可收敛：**积压吐完即收尾**，不能写成"还有内容或还在结束中"这类恒真条件
2. 重入判断只查动画帧句柄，**不能被长期存在的兜底定时器阻塞**（否则流会断死）
3. 时间增量必须钳制（上限 0.1s），否则从后台切回前台会一次性喷完积压
4. 后台时用低频兜底按真实流逝时间推进，且**必须在兜底路径补发结束回调**
5. 采用 abort / 错误结束时**立即收尾**，不等匀速吐完；正常结束才走"吐完再收尾"的丝滑路径

### 5.4 状态纪律（性能）

- 流式正文与思考流走**局部订阅的临时状态**，**绝不进全局状态**（每个 token 触发全列表重渲染 = 卡顿与耗电）
- 全局只存低频相位：等待 / 思考 / 正文、请求 ID、重试提示
- 计时秒表高频直改文本节点，不走状态更新
- **思考流不回传给下一轮请求**（省 token 且不破坏前缀缓存，呼应红线 R-T2）

### 5.5 中断与竞态

- 点「停止生成」必须**立即**反馈（按钮变「正在停止…」并禁用），完成后复位
- 生成过程中拦截会话切换/退出，必须**可见提示**，禁止静默拦截（静默 = 用户以为按钮坏了，属红线 R-P3 同类）
- 等待超过 8 秒必须显式提示（深度档首字等待更长，更要提示）

## 6. 手势与触觉（Android）

| 交互 | 规格 |
|---|---|
| 拍题 | 相机快门有即时视觉反馈（快门白闪 ≤ 120ms）+ 轻触觉 |
| 判题结果 | 答对/答错用**不同**的轻触觉（可关闭）；错误触觉不做连续震动 |
| 长按 | 长按文本选中/复制，**不要**自造长按菜单覆盖系统行为 |
| 上滑关闭 | 面板上滑关闭时跟手（拖动距离即位移），松手按速度决定吸附方向 |
| 下拉 | 首页下拉不做"刷新"（刷新对学习无意义），改为下拉显示「今日待学」摘要 |

触觉纪律：触觉只用于**结果确认**（提交、判分、上传完成），不用于过程装饰；用户可一键关闭。

## 7. 降级与性能红线

| ID | 规则 |
|---|---|
| M1 | 首屏**不得有阻塞性动效**：首屏零学习成本是产品红线（R-P1），动效不得让第一句话的输入被延迟 |
| M2 | 任何动效不得让交互可用时间延后超过 200ms |
| M3 | 同一屏同时动画元素 ≤ 4 个；列表只给首屏可见项做入场 |
| M4 | 低端机检测（内存/帧率）自动降为 reduced |
| M5 | 流式渲染不得因动效掉帧：帧率 < 45fps 时优先砍动效，不砍流式 |
| M6 | 动效不得依赖外部资源（字体/图片）才能正确呈现 |

---

## 8. 无障碍

1. 系统「移除动画」→ 强制 minimal，且**不给用户反向覆盖的入口**
2. 信息不得**只靠动画**传达（例：答对不能只有对勾描边，必须有文本/图标终态）
3. 信息不得**只靠颜色**传达（答对/答错同时有图标与文案）
4. 动效不遮挡内容；自动滚动不强制移动用户视口
5. 触觉可关闭；关闭后所有信息仍完整

| ID | 验收项 | 通过标准 | 级别 |
