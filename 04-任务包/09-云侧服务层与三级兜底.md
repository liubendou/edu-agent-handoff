## 4 完成判据

### 4.1 机检

命令：`./gradlew :core:network:test`（须全绿，输出测试数）。必须包含：

| 测试 | 断言 |
|---|---|
| 前缀哈希 | **连续 50 次** `prefixHash()` 完全一致；仅版本升级时变化（S1.2） |
| 八段顺序 | 请求体断言顺序 = `SYSTEM → PSY_INDEX → CATALOG →〔断点〕→ SKILL → PROFILE → TASK → HISTORY → RETRIEVAL`（S1.1） |
| 断点纯净 | 断点前**无**时间戳/日期/UUID/会话 ID/用户名/请求 ID/时区等随会话变化内容（R-T2） |
| CATALOG 版本 | `CATALOG` 段 `catalog_version` == 端侧编译期常量（R-T8/S1.7） |
| 默认 Flash | 新会话默认 `FLASH`；手动切 `PRO` 即时生效（S1.4/R-T7） |
| 升级仅一次 | 注入一次失败 → 自动升 Pro 且**只升一次**；再失败不循环（S1.5/R-T6） |
| 升级后锁定 | 升级后本会话剩余回合保持 `PRO`（D5/S1.6） |
| 判废判定 | **缺签名必判废**；**签名齐全不误判**（S1.7/K1.4） |
| 三级兜底链 | 逐级注入：① 升级重试 ② 纯文本（必有内容）③ 显式告知+重试入口；任何情况**无空白回合/静默失败**（S1.8/R-T5） |
| 注入器三态 | `FAIL_ONCE` / `FAIL_ALWAYS` / `MISSING_SIGNATURE` 均可复现（D7/E3） |

### 4.2 人工检查点（非程序员可执行）

| # | 你做什么 | 看到什么算通过 | 不通过退回本步哪一项 |
|---|---|---|---|
| 1 | 抓一次请求体（Chucker/抓包） | 八段顺序与 §6 一致，`CATALOG` 带版本号 | §0 八段装配（S1.1） |
| 2 | 连续发 50 次同档请求，比对断点前内容 | 哈希完全一致 | §0 前缀哈希（S1.2） |
| 3 | 跑失败注入（`FAIL_ONCE`） | 只升 Pro **一次**，随后锁定 Pro | §0 升级策略（S1.5） |
| 4 | 跑失败注入（`FAIL_ALWAYS`） | 走完三级：纯文本 → 显式告知+重试入口；**不出现空白回合** | §0 三级兜底链（S1.8） |
| 5 | 跑缺签名注入（`MISSING_SIGNATURE`） | 被判废并进兜底；签名齐全的输出不被误判 | §0 validator（S1.7） |

## 5 本步红线

| ID | 红线（逐字） | 本步拦截手段 |
|---|---|---|
| R-T1 | 模型只输出目录内零件指令，绝不输出可执行 UI 代码 | 白名单校验 + 抓包比对 |
| R-T2 | 断点前三段逐字节稳定，禁止随会话变化的动态内容 | 预渲染 raw + 50 次哈希比对 |
| R-T3 | 新增零件必须同时更新端侧目录 + 云侧第 3 段 + 签名矩阵 | CI 三处 asset diff 校验（本步读 JSON 校验） |
| R-T4 | validator 不得被开关绕过，禁止 feature flag 跳过校验 | 代码评审：无跳过分支 |
| R-T5 | 判废必须走完三级兜底，禁止静默丢弃 | `FallbackController` 状态机单测 |
| R-T6 | 自动升级 Pro 只能一次，禁止升级循环 | `EscalationPolicy` 只升一次单测 |
| R-T7 | 默认必须 Flash，任何人不得改成 Pro | 默认值断言 |
| R-T8 | 端侧目录版本号必须写入第 3 段；旧版本号不得继续使用 | `catalog_version` 断言 |
| R-T9 | 不允许放宽签名矩阵（必需→可选） | 矩阵读自 `signature-matrix.json`，不改写 |
| R-C1 | 不得编造来源、引用、研究结论、教材页码 | `tool_card` 无来源不渲染 |
| R-C2 | 搜索结果与识图结果必须携带来源或可核对原件 | `results[].source` 非空断言 |
| R-D4 | 日志中不得出现成绩、姓名、情绪内容明文 | 日志脱敏 + 抽查 |
| D2 | 断点前内容任何改动，提交说明必须写明「是否影响断点前内容」 | 提交规范 |
| D4 | 判废率/升级率/兜底触发次数持续上报，禁止降级为 debug 日志 | 6 事件名必报 |
| D7 | 提测前必须提供可复现的失败注入手段 | `FaultInjector` 三态 |

## 6 禁止事项

1. 禁止加任何跳过 validator 的 feature flag / 开关（R-T4）。
2. 禁止把默认模型改成 Pro；非失败场景不得改用 Pro（R-T7/R-T6）。
3. 禁止升级循环（R-T6）；禁止升级后回退 Flash 断缓存（D5）。
4. 禁止在断点前三段插入时间戳/日期/UUID/会话 ID/用户名/请求 ID/时区等动态内容（R-T2）。
5. 禁止判废后静默丢弃或直接空白回合（R-T5/R-P3）。
6. 禁止用 Ktor 做 SSE；SSE 走 OkHttp 原生流（§1）。
7. 禁止把 `judge_fail/escalate/downgrade_2/notice_3/unknown_part/prefix_hash` 降级为 debug 日志（D4）。
8. 禁止编辑/改写 `assets/contract/*.json` 与 `assets/skills`、`assets/psychology`（只读消费）。
9. 禁止 `tool_card` 无 `source` 仍渲染；禁止编造来源（R-C1/R-C2）。
10. 禁止在日志/埋点写成绩、姓名、情绪明文（R-D4）；禁止把 API Key 写进日志或版本库。
11. 禁止在 `:core:network` 依赖 `feature`/`:ui:parts`（§2 方向铁律）；禁止硬编码中文文案（§14.2）。

## 7 交给下一步的接口

**7.1 枚举与常量（逐字）**

| 类型 | 取值 |
|---|---|
| `enum class ContextSegment` | `SYSTEM, PSY_INDEX, CATALOG, SKILL, PROFILE, TASK, HISTORY, RETRIEVAL`（顺序即八段顺序；断点在 `CATALOG` 与 `SKILL` 之间） |
| `enum class ModelPref` | `FLASH`(默认) / `PRO`（↔ DataStore `model_pref`；默认值须等于 `:core:model` 的 `DefaultModel = FLASH`，第 2 步已冻结） |
| `enum class Mode` | `QUICK, STANDARD, DEEP, REVIEW, BOOST`（定义于 `com.eduagent.core.model.Mode`，与第 7 步同源） |
| `enum class TurnState` | `IDLE, REQUESTED, STREAMING, VALIDATING, RENDERED, ESCALATED, PLAINTEXT, NOTICE`（§7 状态机） |
| `enum class RejectReason` | `SYNTAX, NOT_IN_CATALOG, MISSING_FIELD, SIGNATURE_MISS`（validator 四步顺序） |
| `enum class FaultMode` | `NONE, FAIL_ONCE, FAIL_ALWAYS, MISSING_SIGNATURE` |
| 预算常量 | 前缀 `≤6k`、断点后 `≤6k`、输出 `≤2k`（D17）；判废率 `<5%`、升级率 `<10%`、前缀命中率 `≥70%`（D15/D16） |

**7.2 端口（Kotlin 签名）**

| 类型 | 签名 | 说明 |
|---|---|---|
| `data class Segment` | `(id: ContextSegment, raw: String, order: Int, afterBreakpoint: Boolean)` | 单段 |
| `data class AssembledContext` | `(prefixRaw: String, prefixHash: String, suffixRaw: String, catalogVersion: String, segments: List<Segment>)` | 装配结果 |
| `interface ContextAssembler` | `fun assemble(input: TurnInput): AssembledContext`；`fun prefixHash(): String` | 八段装配 |
| `interface DeepSeekClient` | `fun stream(systemPrompt: AssembledContext, pref: ModelPref): Flow<TokenChunk>` | **实现第 7 步 `TokenSource`**；SSE 走 OkHttp |
| `sealed interface ValidationResult` | `Rendered` / `Rejected(reason: RejectReason, missing: List<String>)` | validator 结果 |
| `interface PartValidator` | `fun validate(envelopes: List<PartEnvelope>, mode: Mode): ValidationResult`（`PartEnvelope` 定义于 `:core:model`，来自第 7 步 `StreamUnit.envelope`） | 校验顺序：语法→白名单→必需字段→矩阵 |
| `interface EscalationPolicy` | `fun onFail(sessionId: String): ModelPref`；`fun isProLocked(sessionId: String): Boolean` | 只升一次 + 锁 Pro |
| `interface FallbackController` | `fun next(state: TurnState, reason: RejectReason?): TurnState` | 三级链状态机 |
| `interface FaultInjector` | `fun current(): FaultMode` | 开关式失败注入（debug/测试） |
| `interface EventReporter` | `fun report(name: String, payload: Map<String, String>)` | 6 事件名 |

**7.3 埋点事件名（§7 逐字，禁止降级 debug）**

`judge_fail`、`escalate`、`downgrade_2`、`notice_3`、`unknown_part`、`prefix_hash`。

**7.4 三级兜底链（§7/D3 逐字）**

| 级 | 动作 | 用户可见性 |
|---|---|---|
| 1 | 自动升 Pro 重试**一次**（带失败原因回灌；升后锁定 Pro 至会话结束） | 沿用等待态，**不得弹提示** |
| 2 | 降级纯文本回答（不用零件，必有内容） | 呈现为普通段落，**不做红色报错框** |
| 3 | 显式告知：「这次没组织好，我换个说法」+ 重试入口 | **必须可见**（R-P3） |

**7.5 第 10 步集成入口**

- `:core:network` 提供 `DeepSeekClient`（第 7 步 `TokenSource` 的真实实现）+ `ContextAssembler` + `EscalationPolicy` + `EventReporter`。
- `:core:domain` 提供 `PartValidator` + `FallbackController`；`TurnState` 驱动 UI 相位。
- **JSON key（零件信封，§4 逐字）**：`v`(int=1)、`id`、`type`、`payload`；`tool_card.results[]` 的 `{title, url, snippet, source}` 中 `source` **必填**。
- Base URL 与 API Key 由 `:core:network` 内部配置提供；**密钥不进版本库、不进日志**。端点不得写死在业务代码里。
